### ADR-039 — Migration 0019 (the wiki authority boundary) BUILT through four ratchet rounds and DEPLOYED; the first RUNTIME-IMAGE-FIRST ceremony (2026-07-25)

**Decision:** WB-R21's boundary defect is **closed in production**. The authority domain no longer VETOES a document retirement or wrong-client correction under a live wiki citation; the wiki converges by MARKING its own sources stale from the `document.filing_retired` event. **LIVE: Supabase 19 migrations · Fly `clara-runtime` release v26 (`deployment-01KYC90VPARVFWEE2QDKWBWM7H`) · zero freeze impact** (the consumer is a `startWorld` plugin, not a frozen WDK workflow, so no `_vN` and the 71 frozen entries are untouched).

**Build:** contract v1.0 RATIFIED (`docs/plan/wave-b-migration-0019-design.md`, PR #80/#82) after a Codex design debate returned REJECT-as-build-ready with **8 binding amendments** — the decisive one being that the client-row `FOR UPDATE` the veto held was the publication/retirement **serializer**, so the wiki reads go but the lock stays. Then mutually-blind lanes (1,237-line SQL + a 69-cell battery, neither reading the other) → rig reconcile finding **no build defect** (every first-run failure was a test bug) → **four cross-model ratchet rounds**: R1 2 HIGH + 4 (the writer SAMPLED eligibility instead of locking it; the preserved lock does not order publication against retirement under REPEATABLE READ, since a lock without an UPDATE is not a serialization failure); R2 3 MEDIUM, **two of them introduced by R1's own fixes** (the isolation fix opened a silent event-loss path where an unclassified refusal checkpointed and lost a projection forever; the lock fix completed a reachable deadlock because `retire_wiki_page` requests `firm_event_seq` and is therefore NOT a wait-for-graph leaf); R3 5 MEDIUM + 3 LOW (including `budget_unknown`, a pre-existing config-as-terminal bug that R2's faithful refactor had preserved); R4 one MEDIUM — a fail-open in the LINT ITSELF, where a PostgreSQL `E'…\'…'` escape string desynced its lexer and hid a following dynamic wiki EXECUTE. PR #83. Ceremony kit PR #84; the capability-set fix PR #86.

**The ceremony, as run (owner-granted, agent-executed except the two the classifier gated):** backup-first (`2026-07-25T09-08-56-375Z`, 9,945,853 bytes, **zero 501s**, exit 0, dead-man ping) → read-only preflight (18 migrations · veto helper present · `/ready` 200 · 2 known parked chatTurn runs · 1 parked RPR plan, ruled not a journey in flight) → **quiesce** (owner-`!`; machine stopped, **0** `clara_runtime` sessions, **0** advisory locks) → **deploy the runtime image FIRST** (owner-`!`; release v26; verified beforehand that `main`'s runtime carries 0019's stale lane and NONE of 0020's two-phase authorization) → **prove EXCLUSIVE new-binary leadership** — `WIKI_PROJECTION acquired` logged by the new tag, all ten loops up, exactly one instance, 9 advisory locks where there had been 0 → **atomic apply** (`applied 0019_wiki_boundary · 19 total`; the in-txn tail passed against production) → `notify pgrst` → **post-verify 10/10 green** (`wave-b-0019-postverify.sql`: veto helper GONE, both authority fns wiki-clean AND still serializing on the client row, stale columns + paired CHECKs + all six indexes, writer runtime-ONLY ACL, no `wiki.citations_staled` type, `stale_citation` lint class, `clara_runtime` still has NO SELECT on `document_filings`, the §1b isolation floor live, the closed set holding, all three `wiki_pages` lockers taking the client row first) → **catch-up scan returned ZERO pairs** exactly as the contract predicted (pre-0019 the veto made "active page citing a retired filing" unreachable, and runtime-first opened no window), so the marking verb was correctly not needed → post-verify: 30 active pages unchanged, 0 stale marks, sightings 24 unchanged, books 35 unchanged, `/ready` true with **zero warnings**.

**Why (recorded lessons):** (a) **Runtime-image-first has a failure boundary DB-first does not**: if the migration had aborted, the new image would have sat harmless behind its per-event `to_regprocedure` gate with the old veto intact. The cutover point is *exclusive new-binary lock acquisition*, never "the image is up" — an old instance can hold the advisory lock and keep skipping events. (b) **Across both 0019 and 0020, not one finding was caught by the lane that wrote the code** — every one came from an independent adversary asked specifically what the LAST fix broke, and in three separate rounds the previous round's fix WAS the new defect. (c) The recurring defect class is narrower than "bugs": **documents claiming properties the code did not have** — a whitelist described as closed that was a fixed list, a binding described as enforced that was audit-only, an "only channel" that was not the only channel — and in four cases a green test pinned the CLAIM rather than the behaviour. (d) A ceremony probe must be proven non-vacuous: probe 9 was written as a fixed twelve-signature list, false-failed the moment 0020 existed, and is now a capability set that still catches a planted rogue (PR #86).
