### ADR-025 — Wave A2 (sales-invoice/AR + MyInvois XML + standing rules) inserted before Wave B; the auto-post law scoped; consent scoped to cross-border egress (2026-07-21)
**Decision:** The next build target is **Wave A2 — the sales-invoice/AR wave**, deliberately inserted BEFORE Wave B as the completion of the daily loop's transaction symmetry (the AR half WA-R1 carved out of Wave A; planned in no other wave). The ratified contract of record is `docs/plan/completed/wave-a2-ar-myinvois-contract.md` v1.0 + `wave-a2-migration-0015-design.md`, carrying owner rulings **WA2-R1..R14** (grill + delta-ratification, all playback-confirmed). Headlines: (1) intake = PDF/image via the existing pipeline + **MyInvois UBL XML file-upload parsed LOCALLY** — a **dedicated `local_facts` task lane with its own non-frozen matcher-pattern consumer** (the frozen Azure consumer can never claim it — dispatch is lane-based), the egress claim gate stays **LANE-keyed** with a new **lane↔engine DB CHECK**, and a **DB-enforced attribution write-gate** (structured_parse field_paths matching the attribution patterns must be on the supplier allowlist or the write refuses); no MyInvois API pull, no issuance, no authority-verification this wave (offline structure+arithmetic only, envelope facts recorded authority-unverified). (2) **SST 3-leg split + CN/DN posting build NOW** (owner overrides of defer-recommendations; the RPR eval corpus carries zero tax and zero CN — rig fixtures + official LHDN SDK samples carry the proof; recorded residual: the XML parser ships unproven against a real validated e-invoice until first live use). (3) **Standing rules = bounded auto-POST**: a human-signed rule (ADMIN+ sign floor) IS the posting authority; a new DEFINER `execute_rule_post` (login-direct to `clara_runtime_login` ONLY — the `record_rule_resolution` grant pattern) posts matching routine drafts THROUGH the unchanged approve predicate wall with `checker_actor = rule.signed_by`; every bound re-derived in-fn at execution (direction-aware account match, whole-entry constraint, NOT high-stakes, cap, FOR-UPDATE-serialized window count, hard expiry, revision current); rule-posted approvals write NO sightings (rules never breed from their own output); visible receipts + human acknowledgement + reverse-not-delete. **The "no auto-approve ever" invariant is hereby SCOPED to "no *unbounded/agent-initiated* auto-approve"** — S6-R6's named successor arriving as designed; ADR-015's agent-never-signs stays the absence of any agent/wake entry point (the agent role gains ZERO EXECUTE), and this ADR owns honestly that `clara_runtime_login` — the trusted runtime substrate — now carries a posting-capable entry point whose structural wall is the in-fn gate set, not the caller identity. Self-growth is ENABLED per WA2-R12-as-resolved: the agent proposes HIGH-CONFIDENCE autopost rules by professional-accounting judgment + knowledge-lifecycle confidence mechanics (KB-informed once Wave B lands; the wiki informs, never creates/widens/triggers — the Layer-2-only condition), over a ≥3 human-approved-sightings structural floor; NO sign-time widening rate-limit (retire-old + fresh-admin-signature per widening is the control); hard 12-month expiry, never auto-renew. (4) **WA2-R14: the WA-D1 consent gate is SCOPED to cross-border egress** — a locally-parsed document skips the per-client consent hold (no PDPA cross-border basis; the 0014 precedent extended from a document class to a processing class); every Azure/OCR path keeps it unchanged. **Recorded residual:** a locally-parsed e-invoice's customer PII lands in the DB without a consent row, governed by RLS + the books' controls rather than the egress registry; and the OCR lane's verbatim-field_path attribution trust model is an inherited weakness the new write-gate does not cover (named follow-up). (5) Bundled lanes: the **R2 off-site backup wiring on a separate Fly app in `sin`** (owner-accepted custody tradeoff; dead-man's-switch alarm) and the eval = **RPR FY2025 sales + JVs** (AR gate EXACT: Σ 6 invoices = RM 1,973,332.91 = P&L revenue; one customer with the D&Dream→Dare-To-Dream rename as a first-class alias eval case; the payroll subtree consent-excluded, never uploaded).
**Why:** The full design ladder ran: owner grill (13 rulings) → a 9-lane grounding fan-out (which found the AB-3 pin ALREADY as-built in 0011 — the wave preserves it — and that the RPR corpus is a first-and-final winding-up set whose Σ-invoices ties the GL exactly) → contract draft → **dual design review** (native SOUND-WITH-FINDINGS 14; independent adversarial FLAWED 12 — the Codex lane was credit-blocked until 2026-07-25 and replaced by the second fresh-context native lane, the ADR-023 fallback pattern). The adversarial lane materially changed the design: it proved the first egress fix (a services-layer engine router) was itself unsound — dispatch is lane-based and engine-blind, `engine_id` a free intake parameter — forcing the dedicated-lane architecture; proved the "structural" buyer-TIN exclusion was runtime naming discipline (`persist_document_extraction` writes field_paths verbatim); and caught the split-laundering, sales-never-fires, window-race, and forged-approval-core holes in the rule executor. → **A 12-probe empirical battery on a self-stood-up throwaway PG17.6: 8/8 SUPPORTED + bonus, 0 refuted** — every attack live-demonstrated as-built and every prototyped gate proven to close it (plus one build item: the lane↔engine CHECK rejects `finalize_document_intake`'s own `fixture-engine` default — 0015 must retire it). → One consolidated owner delta-ratification (R12 resolved, R14 taken, contract ratified).
