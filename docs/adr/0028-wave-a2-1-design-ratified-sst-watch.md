### ADR-028 — Wave A2.1 design RATIFIED (contract v1.0); purchase "input tax" corrected to a visibility split; the SST watch is a dedicated non-blocking object; cross-model design debate adopted as a design-phase practice (2026-07-22)
**Decision:** The Wave A2.1 design is **RATIFIED** — `docs/plan/wave-a2.1-contract.md` v1.0 (PR #51), rulings WA21-R1..R12. Headlines: (1) the **STRUCTURAL SST-registration watch** is a dedicated **non-blocking `compliance_watch`** state machine (per-client **per service group** — Group G and Group I sums do not aggregate), fed by an `entry.approved` spine consumer + a daily repair reconciler, computing the **statutory month-end rolling test with earliest-crossing detection** (s.12(2): the month-end evaluation IS the law), with tri-state effective-dated turnover classification (missing = `unknown_or_mixed`, never excluded), an effective-dated service-group threshold schedule, human-attested future method (or an honest `not_assessed`), audited dispositions, and surfacing via a new queue `row_kind` + a labeled `get_context_pack` block — never `open_questions`, never anything that can block or post. (2) **Purchase-side SST is a VISIBILITY split** — the ADR-026 deferral's "input tax" wording was a misconception: SST has **no input-tax credit** (regime doctrine); the split is a tied SST-portion-of-cost leg inside P&L via a new `special_acc_type`, human lanes only. (3) **Sales-direction autopost lifts for ALL corroborated sales** (owner ruling) — the OCR class confined to a nine-control envelope (distinct `ocr_sales` evidence class; positive polarity evidence via the doc-type classifier — making the classifier a dependency of the lift; TIN/BRN direction match; multi-anchor corroboration; ≥6 sightings; ambiguity→visible skip + suspension) with bounds **same as structured** (WA21-R10, owner override of the tighter-bounds recommendation; build-time adversarial review retains re-open standing). (4) The wave closes ONLY on the §9 live-eval gates W/S/P/C/D (WA21-R12). Evidence in-repo: `docs/plan/research/wave-a2.1/` (the SST statutory fact-sheet — official sources with an explicit not-primary-verified ledger — and the Codex design-debate memo).
**Why (recorded lessons):** (a) **The cross-model design debate caught a shipping-stopper the single-model grounding missed**: a client-scoped `open_questions` row is a HARD blocking gate as-built (`_open_question_blocks` → CLR26 in `_approve_entry_core`), so the initially-favored shape would have frozen a client's approvals AND autoposts the moment the first SST warning raised — the exact "visibility feature blocks legitimate work" failure the house philosophy forbids. Adversarial cross-model review was already house practice for money-touching BUILDS (ADR-026); it is now practice for DESIGN of anything touching the approval path. (b) Research before shape-picking paid: the statutory test is itself a month-end rolling evaluation, thresholds are per service group, B2B-exempt turnover counts while intra-group-relieved turnover does not — none of which the initial three candidate shapes encoded. (c) The industry pattern is unanimous and matches the cardinal invariant: the system of record computes the figure, alerts fire on state TRANSITIONS only, the durable queue surface outranks any notification, and per-turn context injection — not prompt instructions — is what an agent reliably sees. Ref: PR #51, the owner grill of 2026-07-22 (G1–G4 → WA21-R9..R12).
