### ADR-020 — DR full-fidelity profile + the deployment ACL baseline (hardening interlude)
**Decision:** (1) **The production DR profile dumps the security envelope, not just the data.** `db:backup:full` captures FOUR authoritative schemas — `clara`, `workflow`, **`workflow_drizzle`** (the engine's drizzle journal lives in its own schema; omitting it recreates the ceremony-day silent-no-op/CREATE-SCHEMA-collision class), `graphile_worker` — **WITH owners and ACLs**: the two-lane write-confinement wall IS the GRANT/REVOKE matrix plus `clara_fn_owner` object ownership (a SECURITY DEFINER writer executes as its owner), so an owner/ACL-stripped restore is a privilege escalation, not a cosmetic gap. The **default** profile (`db:backup`) remains owner/ACL-stripped and is hereby classified a **diagnostic books snapshot that must never be started as an application database** (its restored `schema_migrations` makes re-migrate a no-op while functions sit deploy-role-owned + PUBLIC-executable); production recovery is full-profile-only. (2) **Roles restore via a reviewed ceremony, not globals.** Cluster roles are in no `pg_dump`, and a raw `pg_dumpall --globals` collides with a fresh project's managed roles — so `deploy/roles-bootstrap.sql` (FRESH-TARGET-ONLY; fail-closed if a login shell is already LOGIN or the override is not exactly 0/1; fail-closed on any clara-role ADMIN OPTION) recreates the complete 10-role census (9 migration roles incl. the two 0006 login shells + `clara_storage_docs`) with exact attributes/memberships/settings; the globals dump is a parity-evidence artifact only. Login credentials re-enter ONLY via the ceremonies (`write-login-ceremony.sql` + the new `read-logins-ceremony.sql`). (3) **The full restore is ordered and verified:** `restore-full.mjs` (one destructive guard: roles-bootstrap → single-transaction restore → the manual ceremony checklist), then the `dr-verify.mjs` battery — self-compare-refusing; completeness-floored on the **on-disk migration sha256 manifest** (a forged name-only ledger fails); row/content parity; role attributes + memberships incl. `admin_option`; ownership + grant matrices (grantor, grantability, column + sequence ACLs); executable-DDL parity (function bodies/secdef, triggers, constraints, indexes, views, types); RLS + policies; a boundary-asserted behavioural 42501 confinement smoke; canary-state parity; documents path-sha↔`source_doc_sha256`; the AP assertion hard-pinned to **net credit−debit** via `clara.trial_balance`; STRICT mode for live drills. CI proves backup→restore→verify **across two independent postgres:17 clusters** (roles genuinely rebuilt from an empty `pg_authid`) on every run. (4) **The HIGH-10 deployment ACL baseline ships as a deploy ceremony** (`deploy/acl-baseline.sql`, NOT a migration — the clara-scoped chain must not own `public`/database ACLs): revoke `public`-schema USAGE from PUBLIC + database TEMP with **snapshot-and-preserve re-grants** (managed service roles keep what they effectively had; re-runs never widen post-baseline roles; the five confined agent/wake lanes lose all `public` reach; CONNECT deliberately kept; full-snapshot fail-closed VERIFY). **The `pg_catalog` side-effect surface (`pg_notify`, advisory locks, `pg_sleep`) is ACCEPTED as a permanent residual on managed Supabase** — superuser-owned, empirically un-revocable by the customer role; low practical severity while the sanctioned agent surface is curated typed reads (the deferred freeform-read LOGIN stays deferred). A restore does NOT carry the baseline — re-applying it is a mandatory post-restore ceremony. (5) The remaining gate items — the fresh-Supabase-project drill execution, encrypted off-site scheduling, freshness alerts, Pro+PITR — are OWNER-GATED acts runbooked in `docs/ops/DR-full-drill.md`, not silently claimed.
**Why:** PART-2's finding-10 gate (REQUIRED before real books — and real books went live at GATE 3) + the HIGH-10 deferral. The recon fan-out found the load-bearing defects by analysis (the `--no-privileges` "full" profile; the missing `workflow_drizzle`; `pg_catalog` un-revocability and the ALTER-DEFAULT-PRIVILEGES no-op proven by non-superuser rig probes); the dual as-built review then earned its keep — Codex xhigh FLAWED with 7 empirically-proven HIGHs (a self-comparing verifier certifying an empty DB; the default-restore narrative reopening the write wall; a roles-bootstrap re-run that would have NOLOGIN'd the live login shells; single-cluster CI making role parity tautological; a wrong AP sign default; grant-option/column-ACL blindness; an unproven TEMP revoke) — closed over TWO fix rounds with a Codex re-verify between (which added 3 more real findings: the `admin_option` blind spot, a deterministic CI role-census mismatch, an override-value bypass). Final adversarial proofs: self-compare REFUSED; forged-checksum ledger FAILED the floor; abort-on-LOGIN-shell and abort-on-override≠0/1 and abort-on-clara-ADMIN all PROVEN; cross-cluster CI-exact round-trip 175 PASS / 0 FAIL; ACL baseline non-breaking (db suite 265/0/11 before and after); all workspace gates green.
