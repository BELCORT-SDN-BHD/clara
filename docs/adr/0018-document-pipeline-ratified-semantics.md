### ADR-018 — The document pipeline's ratified semantics (Slice 5)
**Decision:** Slice 5 realizes the document pipeline with these owner-ratified semantics (grilled 2026-07-18; contract `docs/plan/completed/slice5-document-pipeline-contract.md` v1.2 + companion `slice5-migration-0007-design.md`): (1) **OCR egress = a two-tier gate** — build/ship NOW on synthetic + firm-own data; REAL client documents reach the vendor only after the owner evidences an ADR-011-grade bundle (executed DPA + engagement-letter processor-disclosure clause **firm-wide across every active client** + documented PDPA cross-border basis + no-training/limited-retention terms + minimized payload + tested deletion), enforced fail-closed by `CLARA_DOC_EGRESS_APPROVED` whose OFF state parks OCR tasks at the pre-dispatch claim gate (`queued→held_egress`; no run binds, no vendor call); the real vendor adapter has NO dev bypass. (2) **Engine pin** = Azure Document Intelligence prebuilt-layout v4.0 (API 2024-11-30), Southeast Asia, S0 — snapshotted per processing task; the law stays vendor-agnostic. (3) **Chat attachments ship as a CAPTURE door** (amends the Slice-4 ruling of record: chat may never write books; evidence ingestion is allowed): chip + persist + lane, submit blocks on intake adoption so the `{type:'attachment'}` part is present at `begin_chat_turn`; `chatTurn` stays frozen at v1 so Clara does NOT perceive attachments in-turn — perception (a parts-aware `chatTurn_v2` + a firm-scoped unassigned-document read tool) is Slice 6, and the UI copy states this honestly. (4) **Storage is content-addressed write-once** (`firms/{firm}/docs/{sha256}.{ext}`, upsert=false, never moved, never deleted by any routine principal); the runtime seals the sha↔bytes bond by hashing the spooled stream and re-hashing a readback after upload; the browser never holds a storage credential (transport = runtime-owned store-and-forward on Fly — never the 4.5MB-capped Vercel proxy, never direct-to-storage). (5) **Multi-client filings** — ONE document row per (firm, sha256) + historical `document_filings`; unassigned ⇔ zero active filings; provenance is filing-bound and two-layer: admission derives `filing_id` server-side in `_draft_entry_core` + enforces the citability law (ACTIVE filing AND `bytes_verified_at`), `approve_entry` re-affirms, and the DEFERRABLE belt validates congruence against the BOUND filing regardless of retired state — so the correction transaction commits while history stays verifiable. (6) **Both legacy ingest writers retired** (bodies → deterministic refusal, EXECUTE revoked, allowlist row deleted); the verified-intake finalizer is the SOLE document creator (closes HIGH-12: a caller-claimed sha is never again ingestable as evidence). (7) **Attribution = deterministic two-lane, no model, no autonomous filing**: a net-new `matcher` consumer on the generalized relay (own advisory-lock leadership, own `(consumer,firm)` checkpoints, own dead-letters + consumer-specific redrive) subscribes to `document.extraction_completed`; lane 1 (authorizing) = a unique role-aware HARD identifier hit recomputed server-side inside `record_rule_resolution` (callers supply neither client nor confidence; EXECUTE held by the `clara_runtime_login` login DIRECTLY — a deliberately narrow surface a pooled SET-ROLE session cannot reach); lane 2 (advisory) = exact name/alias hits as candidates only; conflicts abstain with the conflict REPRESENTED (identifiers deliberately non-unique across siblings); assignment stays a human act in Slice 5; all model machinery waits behind the Phase-5 eval gate; confidence never displays as a percentage. (8) **Correction = refuse-until-reversed + a guided case**: `retire_document_filing` refuses with structured blockers while live posted entries OR live drafts cite the document; the sanctioned path is preview (read-only blast radius) → propose (immutable hash-bound plan + books_version; any intervening event stales it) → approve by a DISTINCT eligible checker (attestation is not a bypass when another checker exists — the 0004 house law; solo-attest only when solo) requiring an authoritative human/rule DESTINATION attribution (a ≥0.95 document-subject resolution for the target client) → ONE bounded transaction: whole-consequence reversal mirrors, drafts → a real `withdrawn` journal status (never deleted; lines frozen; excluded from every book-effect read, included in history), source filing retired, target filing ensured, one aggregate `document.correction_applied` + ordinary child events; closed periods HARD-BLOCK at approve (honest-state: no period model exists yet — `_correction_period_state` is the single extension point reporting `no_period_model`); approve is human-only forever. (9) **Document metering = a separate fail-closed budget** with durable reservation semantics (conservative declared-size reserve → post-scan resize → settle at actual pages → refund on failure; adoption TRANSFERS the charge, the legacy-upgrade branch charges fresh; settled usage counts against a lowered limit — conservative daily accounting). (10) **Retention = honest states**: `unanchored` (no sentinel; undeletable while unanchored) → first filing anchors (FY-end + statutory offset + 7y; conservative floor recorded when FY data is missing) → MAX across active filings; `retain_until` persists across unanchor→re-anchor so floor-never-shorten stays monotonic; audited admin legal holds independent of the clock; no purge machinery in v1. (11) **Freshness narrows ADR-016's asymmetry** (owner-ratified delta): a null-client event carrying a `document_id` is relevant to client X iff an ACTIVE filing document→X exists — an unassigned document's ingest/extraction events stale NOBODY, `document.filed` stales exactly its filed clients, `document.correction_applied` is exempt (its children carry the staleness); non-document null-client events keep firm-level staleness. (12) **Taxonomy v2 activated in-migration** with full coverage + the quiesce-aware cutover protocol (residual v1 document intents/held rows cancelled with an audited reason). (13) **MyInvois UBL XML = store-only** (flagged "e-invoice — stored, not parsed") until the coding slice. **As-built §3.10 amendments of record (surfaced by the build's independent lanes, adjudicated as matrix omissions):** migration `0008_runtime_read_surface.sql` adds READ-ONLY runtime visibility on (a) the matcher's lane-2 inputs (extractions/regions/clients — the granted aliases/identifiers row proved matcher-side computation was the intent) and (b) the runtime's OWN control tables (intakes/processing tasks/reservations — the §3.9 reconciler design requires seeing queued-unbound tasks; the read grant closes an otherwise-irreducible finalizer crash window); DML remains writer-only. The Slice-5 failure-code map is CLR15–20 (the contract defined only CLR02 — a process lesson: enumerate the code map at design time).
**Why:** Ten owner rulings + three owner-delegated decisions resolved by industry research + cross-model debate (evidence in `docs/plan/research/slice5/`), integrated through the three-stage ladder: dual design review (25 findings), dual delta re-review (20 findings + three owner-ratified amendments), then a five-lane build — a Codex migration lane and a CONTRACT-BLIND native rig lane running in parallel (the blind lane's 68-test battery surfaced 5 divergences, ALL adjudicated for the migration against house precedent, plus two grant-matrix omissions surfaced live by the matcher and runtime lanes and fixed as 0008), a runtime intake/workflow lane (transport-true E2E: HTTP stream → spool → scan → canonical → readback → finalizer → real WDK OCR run → regions, with SSE liveness proven under parse load), a matcher lane (router regression A/B-proven byte-identical), and a dashboard lane. Final integration: full db suite 188 tests green (181 pass / 7 gated skips) incl. the deploy-onto-existing backfill drill with its atomic-abort proof; runtime suite 94/94 after the v1-era fixtures were adapted to the retired-writer + taxonomy-v2 reality (the `rig.%` reserved test namespace).
