### ADR-015 — Write-authorization is lane-split by GRANT, not detected at runtime (Slice 2 C3-iv)
**Decision:** The structural read/write-authorization boundary (Gate-1 C3, invariant 4) is realized by **splitting each mutating writer into two entry points that trust exactly one identity source** — a *human* entry (`draft_entry`, `approve_entry`, …) granted only to `clara_authenticated`, trusting `request.jwt.claims`, with firm = the sub's LIVE active membership (live revocation); and a `wake_*` entry granted only to the wake role(s), trusting the wake credential, with actor = the global agent user (never `on_behalf_of`) — over a shared, **ungranted** internal `_core`. There is **no** wake variant of `approve_entry`/`reverse_entry`: agent-never-signs is the *absence of an entry point*, not a runtime check. Read scoping is **role-pinned in the RLS policy** (human policy → `jwt_firm()`, agent policy → `wake_firm()`), never a single dual-source resolver; and a firm's parentless writes stamp the writer's already-validated firm, never a re-derived ambient `coalesce(wake, jwt)`.
**Why:** The original design detected the lane *inside* the writer by role membership. This is **impossible** (empirically confirmed, PG16): inside a `SECURITY DEFINER` function PostgreSQL sets `current_user` to the function owner and `session_user` to the login — the `SET ROLE`'d caller is invisible. Deciding the lane by *which function you hold EXECUTE on* makes a forged `request.jwt.claims` in an agent/runtime session inert (the agent roles hold no EXECUTE on any human entry point; the runtime login is not a member of `clara_authenticated`) with no in-function detection, and stamping the validated firm blocks a foreign `wake_secret` from redirecting a human write. Ratified after a mandatory dual-lane adversarial review whose **design pass AND code pass both returned FLAWED first** and were corrected before merge (the design's impossible in-definer detection; the code's proactive-consume race, an approved-entry line-reparenting hole, cross-firm credential-revocation scoping, an agent-as-owner lockout, a `shares_firm` oracle, and non-superuser deploy blockers — all reproduced-closed). Ref: ARCHITECTURE §3.2; Slice-2 design v2 §A.
