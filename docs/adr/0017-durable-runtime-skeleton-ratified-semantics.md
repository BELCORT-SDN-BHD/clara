### ADR-017 — The durable runtime skeleton's ratified semantics (Slice 4)
**Decision:** Slice 4 realizes ARCHITECTURE §4 with these owner-ratified semantics (grilled 2026-07-18): (1) Slice-4 chat = READ-ONLY advisor (`get_context_pack` + typed reads; writes debut Slice 6); (2) wake consumption = project-only (held tasks + outbox; no autonomous runs); (3) chat model = OpenAI via the AI SDK seam, the model id DURABLY SNAPSHOTTED per task at admission — a config change never retargets an in-flight/parked run (the config-snapshot corollary of ADR-010; prompt + tool registry live INSIDE the frozen body's import closure); (4) metering = 1M tokens/day + 3 concurrent COMPUTE runs per firm, fail-closed, atomic admission (advisory-lock + count + insert in one txn), usage consumed at settle from per-segment durable checkpoints (overshoot honestly bounded by admitted in-flight runs; cancel-after-spend cannot evade the ledger); (5) clarify answerable by ANY write-capable member (`asked_of` + `answered_by` both recorded), 14-day visible expiry, DB-linearized single-winner transitions (clock_timestamp-after-lock), lease-based hook delivery (engine-single-shot + HookNotFound = already-delivered); (6) chat visibility = PRIVATE-BY-DEFAULT + one-click share-to-firm (a 16-product exemplar survey + an independent Codex consultation both converged on the two-layer model: run receipts firm-visible always, transcripts private; the masked task view carries NO private-session linkage; the owner has NO routine transcript access; a departed author's un-shared transcripts are unreachable until the deferred compliance export — accepted); (7) cancel by any write-capable member, cascading to pending interruptions + held outbox rows; (8) traces = Postgres-only (the vendor path is ABSENT per ADR-011), 90-day started_at-keyed audited prune; (9) deploy = park→clean→deploy sequencing (T2-48h sign-off, then the owner-approved spike-schema drop, then Fly `sin`, one always-on non-HA machine); (10) **event-law scope clarification (supersedes ONLY the universal quantifier in ADR-016(3)):** a DOMAIN writer is one whose mutation is represented by a catalogued `event_types` fact and feeds projections/taxonomy/freshness — such writers keep same-transaction emission; runtime-control mutations (sessions, messages, tasks, interruptions, outbox delivery state, metering, traces) emit NO domain events; governance routines stay audited + idempotent via `audit_log` + `_reserve_op`. Structural boundaries fixed of record: the chat-ingress trusted-service boundary (pinned JWT validation; the principal resolved from LIVE membership via a definer fn, never JWT claims; ONE central transcript-authorization module; DB RLS backstops the human lane); governance acts ride ONLY the human lane (dashboard→PostgREST — the runtime login is not a `clara_authenticated` member, structurally); two single-membership logins/pools (SET TRUE + INHERIT FALSE); plaintext secrets never transit WDK step IO (step IO is durably persisted); wake credentials minted per execution attempt.
**Why:** Grilled decision-by-decision, then the three-stage dual-lane ladder — design review (native SOUND-WITH-FIXES + Codex FLAWED, 31 findings), delta re-review (CLEARED-WITH-NOTES + STILL-FLAWED-additive, 19), six empirical probe rounds (48 assertions; three load-bearing WDK discoveries: an unclosed stream readable never signals done; hook tokens are engine-enforced single-shot; the memoization boundary is exactly step completion), a four-lane build with a CONTRACT-BLIND rig lane (three rounds to 48/48; three real defects found→fixed→re-proven: session-author validation, clarify linearization, the FX4 cross-task token race), and a live-verifying as-built review (Codex xhigh: 16 findings incl. 2 CRITICAL — SET FALSE memberships that broke every pool checkout, and a production image missing the engine's runtime require — all closed and re-verified; the security core positively live-confirmed: five-lane EXECUTE matrix, zero PUBLIC, FORCE RLS ×12, masked-view no-oracle, credential containment, JWT negatives).
