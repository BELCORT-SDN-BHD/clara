## ADR-029 adversarial ratchet — Round 1

Read-only review; no files changed.

1. **[SEVERITY CRITICAL] Opening entries escape the atomic K5/K6 protocol through ordinary journal verbs.** — Evidence: K3 creates normal `journal_entries` with only `is_opening_balance=true` distinguishing them ([0017:2200](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0017_wave_b.sql:2200)). Generic approval locks and approves any draft without rejecting that flag ([0016:1252](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0016_a21_compliance_watch.sql:1252)); `revise_entry` likewise accepts it ([0016:4807](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0016_a21_compliance_watch.sql:4807)); `withdraw_draft` can orphan its `opening_items` row ([0009:1893](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0009_coding_floor.sql:1893)); `reverse_entry` copies the flag into a current-date reversal ([0009:1715](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0009_coding_floor.sql:1715)). Reproduction: stage a BEE seed, then call `approve_entry` per entry with a distinct checker; entries approve while the registry remains open and no set tie/finalization occurs. There is also a deadlock: K5 takes the client advisory lock first ([0017:2622](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0017_wave_b.sql:2622)), while generic approval takes the entry row first and advisory lock later ([0016:1265](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0016_a21_compliance_watch.sql:1265), [0016:1346](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0016_a21_compliance_watch.sql:1346)). — Consequence: individually approved, revised, withdrawn, or wrongly dated opening balances; K5 atomicity and sighting quarantine are bypassed. — Minimal fix: CoR every generic lifecycle verb/core to reject `is_opening_balance`; only K-family correction/approval may mutate such entries.

2. **[SEVERITY CRITICAL] “Document-primary” tie-out is only a label; arbitrary keyed or fabricated parsed values pass against a signed document.** — Evidence: `record_opening_target` ignores supplied document fields and forcibly writes `provenance_kind='keyed'` ([0017:1935](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0017_wave_b.sql:1935)). K5 enforces all-keyed only when the registry has *no* tie document; with a tie document it checks only that document’s registry hash ([0017:2628](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0017_wave_b.sql:2628)). Even the parsed writer accepts caller-supplied amounts and merely requires `extraction_ref` to be an object—no extraction row/content validation ([0017:1985](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0017_wave_b.sql:1985)). The shared “document-primary” fixture actually calls the human keyed writer ([wb-fixtures:113](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/tests/wave-b/wb-fixtures.mjs:113)); `recordOpeningTargetsParsed` is never called outside its wrapper. K5 also never revalidates each draft entry’s filing/hash, despite WB-R4 requiring source-document hashes. — Consequence: an arbitrary TB can be approved while a genuine signed TB is decorative. — Minimal fix: with a tie document, require every target to be document-provenance for that exact document/hash and bind extraction references to stored extraction evidence; revalidate every entry’s active filing/hash at K5. With no tie document, require every target keyed and attributed. Replace the happy fixture with the parsed path.

3. **[SEVERITY CRITICAL] B-12 approval and post-finalization lint calculate the tie over different ledgers.** — Evidence: `_opening_seed_deltas(...,true)` considers only seed entries/reversals ([0017:2403](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0017_wave_b.sql:2403)); the `false` branch considers every approved client entry through `as_of` ([0017:2415](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0017_wave_b.sql:2415)). K5 uses the former ([0017:2452](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0017_wave_b.sql:2452)); L4 uses the latter ([0017:3431](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0017_wave_b.sql:3431)). Reproduction: on an active client, approve a normal entry dated `<= seed.as_of`; stage OB figures matching targets but ignoring that entry. K5 passes, then lint immediately reports a critical broken tie. The B-12 test avoids the defect by dating its existing trade in May while `stageBeeSet` defaults to January ([wb-k-approval:269](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/tests/wave-b/wb-k-approval.test.mjs:269)). — Consequence: duplicate or incorrect live-book carry-down can be committed. — Minimal fix: one canonical basis for dry-run, K5, and lint: approved ledger through `as_of` plus pending seed/correction drafts, deduplicated and with identical OBE treatment.

4. **[SEVERITY HIGH] Claimless `clara_authenticated` sessions become cross-firm wiki readers.** — Evidence: both SECURITY DEFINER reads treat `jwt_firm() IS NULL` as proof of the runtime lane and derive firm ownership from the caller-supplied client ([0017:1465](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0017_wave_b.sql:1465), [0017:1489](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0017_wave_b.sql:1489)). Both authenticated and runtime roles have EXECUTE. Reproduction: `SET ROLE clara_authenticated`, leave `request.jwt.claims` unset, then call `get_wiki_page(foreign_client, known_slug)`; the definer returns that firm’s content. The W8 cell tests normal JWT and runtime calls, not this branch ([wb-w-wiki:236](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/tests/wave-b/wb-w-wiki.test.mjs:236)). — Consequence: a missing/misconfigured claims context becomes a tenant-data disclosure. — Minimal fix: separate human/runtime functions with disjoint ACLs, or require an explicit trusted runtime lane marker; absence of human claims must refuse, never widen.

5. **[SEVERITY HIGH] WB-R1 missed operational enumerators and the queue CoR can silently miss replacements.** — Evidence: patched consumers cover drafting, coding lanes, autodraft, classify dispatch, and five queue row CTEs ([0017:54](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0017_wave_b.sql:54), [0017:236](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0017_wave_b.sql:236)). 6. **[SEVERITY HIGH] P17 replay cannot rebuild the wiki index, and the battery reconstructs it using live tables.** — Evidence: `wiki.page_published` omits title, counterparty, citations, refs, content, and projected sequence ([0017:1315](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0017_wave_b.sql:1315)). The W4/P17 test obtains page-id→slug mappings from live `wiki_pages` and compares only five fields ([wb-w-pack:150](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/tests/wave-b/wb-w-pack.test.mjs:150)). — Consequence: after loss/truncation, ingest pages disappear and full page/version/provenance state is unrecoverable from events. — Minimal fix: emit a canonical complete reconstruction event for every publication path, including ingest; test rebuilding empty shadow tables using events plus Storage only and compare every reconstructible column/citation/ref.

7. **[SEVERITY HIGH] The hard wiki page cap has a check-then-insert race.** — Evidence: a missing slug causes an unlocked count followed by insert ([0017:1174](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0017_wave_b.sql:1174)). Two sessions at cap−1 publishing different slugs both see room and both succeed. The battery is sequential ([wb-w-wiki:192](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/tests/wave-b/wb-w-wiki.test.mjs:192)). — Consequence: the ratified hard cap is exceedable. — Minimal fix: client-scoped advisory/row locking around count+insert, or a transactional counter; add a two-session race.

8. **[SEVERITY HIGH] Wiki document provenance is firm-bound but not client-bound.** — Evidence: document citation/ref FKs cover only `(document_id, firm_id)` ([0017:495](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0017_wave_b.sql:495), [0017:535](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0017_wave_b.sql:535)); the writer checks only whether the document is consent evidence ([0017:1233](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0017_wave_b.sql:1233)). — Consequence: client A’s page can cite a document filed exclusively to client B, poisoning provenance and client isolation. — Minimal fix: require an active `(document_id, client_id)` filing for every document citation/ref and verify prior-GL detail belongs to that source.

9. **[SEVERITY HIGH] `obe_plug` implements the opposite of binding AMB-4.** — Evidence: AMB-4 requires `p_lines=NULL`, amount in `p_item`, and marker resolution ([adjudications:15](/C:/Users/zhant/Desktop/clara-rebuild/docs/plan/research/wave-b/0017-ambiguity-adjudications.md:15)). No battery cell executes `obe_plug`. — Consequence: arbitrary ordinary-account balances can masquerade as the single OBE plug. — Minimal fix: dedicated AMB-4 branch resolving the OBE marker from `amount_cents`; reject any supplied lines and add polarity/zero-net tests.

10. **[SEVERITY HIGH] Fixed-asset supersede leaves both old and replacement register rows active.** — Evidence: every drafted fixed asset is inserted with `status='active'` ([0017:2260](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0017_wave_b.sql:2260)); correction approval supersedes only `opening_items`, never the old `fixed_assets` row ([0017:2914](/C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0017_wave_b.sql:2914)).
