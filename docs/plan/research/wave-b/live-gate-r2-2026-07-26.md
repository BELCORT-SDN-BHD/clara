## ★ THE DB REFUSED HALF THE TICK LIST, AND IT WAS RIGHT

Six of the twelve owner-confirmed ticks were refused **CLR23 `registration_conflict`** —
*"registered name match is ambiguous without a registration number."* The refused set is exactly
the counterparties that **already exist in RPR carrying a real registration number**, created
2026-07-19/22 from actual supplier invoices:

| counterparty | existing registration |
|---|---|
| BRIGHTPATH CONSULTANCY SDN. BHD. | `202401047756 (1593602-X)` |
| BUSYSTREET CONSULTANCY SDN BHD | `202101041181 (1441481-X)` |
| PKL GROUP SDN BHD | `202201010448 (1456145K)` |
| ROME PUBLIC ADVISORY SDN BHD | `201501005365 (1130695-T)` |
| KOK LIONG ACCOUNTANCY & MANAGEMENT SERVICES | `1045761P` |
| ROME GROUP SDN BHD | `NOT STATED` |

**A general ledger does not print registration numbers**, so a prior-GL proposal is
name-only. The DB refuses to bind a name-only proposal to a registered legal entity — which is
precisely how a similarly-named company would otherwise be mis-attributed. **This is the
structural invariant working, not a defect**, and no registration number was invented to get
around it.

**The product gap it exposes, honestly:** prior-GL seeding currently cannot enrich a
counterparty that already exists *with* a registration. That needs a human "these are the same
party" act. Worth a deliberate lane rather than discovering it again.

**Also demonstrated:** one refusal never poisoned the batch. Twelve independent tick calls, six
refused, six succeeded — the BatchApprove doctrine held across the whole run.

## Defect found and fixed mid-ceremony

The first `prepare` returned **422 `no_parse_source`** on a ledger holding 1,907 good table
cells. Cause: `superseded_by` chains **per document, not per engine** — `classify_document`
writes a `doc_classify` extraction that supersedes the `ocr` one holding the layout regions
(36 of 38 `ocr` extractions on live are superseded). The `superseded_by is null` predicate I
had copied from the `prior_gl.line` query therefore returned zero cells for every classified
document. Fixed in PR #104 by selecting the newest layout extraction **by engine**, mirroring
`readExtractionText`.

**Eleven pure unit tests were green throughout.** The defect lived in a SQL predicate, not in
the parser, so no unit test could see it. It was caught only by running the ceremony on live —
which is the argument for live gates in one sentence.
