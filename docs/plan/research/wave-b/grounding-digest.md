==== READER: prd:wiki+onboarding ====
SUMMARY: PRD.md pins Wave B tightly. §6a (lines 135–142) mandates a Karpathy two-layer knowledge system: Layer 1 is a per-client, Clara-maintained set of interlinked, versioned, provenance-cited markdown wiki pages over immutable raw sources with exactly three operations (ingest, query, lint-on-a-schedule), injected into every context pack but inert on read; Layer 2 is a thin typed authority holding the posting gates (user-gated account-mapping rules, the DB-enforced ≥0.95 client gate, and open-question/must-ask objects with resolution state that block workflows until answered). LAW invariant 14 (line 129) plus the §6a coda (line 142) forbid the wiki from ever selecting an account, lowering a gate, or authorising a write. Onboarding (lines 72, 101–102) must be agent-led clarify-driven interviews that never store flawed data, and ongoing-client carry-down must run through the idempotent carry-forward function with a TB tie-out assertion covering opening GL balances, AR/AP open items, and the FA register + depreciation baseline, followed by KB-wiki seeding from prior data, dry-run review, then commit. Opening balances sit on the high-stakes maker/checker lane (different-human checker, lines 50–53), all numbers are DB-computed bigint cents through named audited functions (invariants 1/6/10), F3 makes a stale KB/wiki state a workflow FAILURE with the wiki update in the same audited transaction (lines 76, 119, 150), and interviews-as-durable-runs must satisfy invariant 13 (durable, resumable, idempotent, server-cancellable).

WAVE_B_PINS:
