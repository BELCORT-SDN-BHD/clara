## Why the audit is evidence and not a formality

Scanned over **all** `clara` functions, not just `SECURITY DEFINER` ones — an invoker helper
called from a definer runs with that definer's authority (0019 ratchet R1 finding 4), so a
definer-only scan would leave the cheapest bypass unexamined.

**Proven to fail on three violation shapes** (rig, migration 20, each injected then reverted):

| injected | result |
|---|---|
| an unauthorized `clara` fn that NAMES `wiki_pages` | `W2/2` — rejected |
| an **overload of an authority name** whose body only CALLS `list_wiki_pages` (names no relation) | `W2/2` — rejected |
| an authority fn **renamed away**, so the audit would scan a short set | `W2/3` — rejected as drift, not passed vacuously |

The third shape is the one that matters most: an audit that silently scans an empty set is
worse than no audit, because it produces a green receipt. Probe 4 additionally asserts the
seven wiki relations still exist and that both regexes match something, so a rename of the
relations themselves cannot clear everything.
