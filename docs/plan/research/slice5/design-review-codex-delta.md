## Part B — new findings

- **[S5-DR2-C1 CRITICAL] Existing document-bearing entries have no `filing_id` migration.** §3.1 immediately requires the new pair, but existing rows carry only document/SHA and reject arbitrary updates through `_tf_entry_immutable` ([§3.1](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-migration-0007-design.md:66>), [0003 schema](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0003_books_core.sql:101>), [immutability trigger](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0003_books_core.sql:349>)). Fix: lock writes; add nullable column; backfill each cited entry to its legacy filing; prove zero ambiguity/misses; replace triggers; then validate the paired constraint.

- **[S5-DR2-C2 CRITICAL] Legacy verification has no valid adoption branch.** Legacy rows must become citable after verified re-upload, but duplicate adoption assumes an existing charge/task and forbids a new task/event—none exists for pre-0007 documents ([citability law](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-migration-0007-design.md:50>), [adoption](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-migration-0007-design.md:95>), [legacy document schema](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0003_books_core.sql:64>)). Fix: a locked claim-only-upgrade branch must seal canonical bytes, stamp verification/path, create the first task/event/reservation settlement exactly once, and preserve filings.

- **[S5-DR2-C3 CRITICAL] [DELTA-OWNER-1] Client-specific egress authority is enforced only by a global flag.** Unassigned uploads OCR before the client is known, while ADR-011 requires specific client authority ([S5-R1](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:24>), [global gate](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:266>), [ADR-011](</C:/Users/zhant/Desktop/clara-rebuild/docs/PROJECTLOG.md:54>)). Fix: separate deployment/vendor approval from document-level authority and bind an evidenced authorization record before real-client egress; define how unassigned matching can proceed without violating that gate.

- **[S5-DR2-H1 HIGH] Taxonomy v2 has a cutover race and leaves v1 work artifacts alive.** Repointing does not neutralize pending `background_review` intents or already-held tasks; an old router batch can also commit v1 routing after the cleanup snapshot ([§3.7](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-migration-0007-design.md:175>), [v1 mapping](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0005_event_spine.sql:448>), [held-task drain](</C:/Users/zhant/Desktop/clara-rebuild/packages/runtime/lib/drain.mjs:13>), [batch taxonomy pin](</C:/Users/zhant/Desktop/clara-rebuild/packages/runtime/lib/relay.mjs:305>)). Fix: publish a quiesce/drain/migrate/deploy protocol and explicitly consume/cancel historical document-review intents, tasks and outbox rows.

- **[S5-DR2-H2 HIGH] [DELTA-OWNER-3] Freshness remains over-broad for new document events.** Extraction and aggregate correction events can be null-client—especially for unassigned/multi-client documents—so the proposed “all other null-client events” rule still stales every client ([§3.7 amendment](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-migration-0007-design.md:192>), [extraction events](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-migration-0007-design.md:106>), [current predicate](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0005_event_spine.sql:500>)). Fix: determine relevance through active filings: none when unassigned, only filed clients when assigned; exempt aggregate events already represented by child events.

- **[S5-DR2-H3 HIGH] Durable tasks cannot be proven bound or retry held egress.** §3.9 refers to “unbound” tasks but has no `workflow_run_id`; its states also omit `held_egress`, although §4.6 promises retryability ([task schema](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-migration-0007-design.md:211>), [egress state](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:265>), [Slice-4 binding precedent](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0006_runtime_core.sql:138>)). Fix: add CAS run binding, legal held/release/retry transitions, and reconciliation for queued-unbound plus stranded-running tasks.

- **[S5-DR2-H4 HIGH] Retention forgets its maximum-ever floor.** Returning to `unanchored` forces `retain_until=NULL`; re-anchoring can then install an earlier date because neither documents nor filings retain the previous clock structurally ([columns](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-migration-0007-design.md:40>), [re-anchor promise](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:272>)). Fix: persist a non-shortenable historical floor or per-filing clock snapshot independently of current anchoring state.

- **[S5-DR2-H5 HIGH] Intake transitions contradict duplicate adoption and polling.** The legal edges omit `duplicate→adopted`, allow terminal `adopted→failed` through “any→failed,” and call one token single-use while requiring it for repeated status polls ([§3.2](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-migration-0007-design.md:80>), [chip polling](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:254>)). Fix: make terminal states immutable, add an explicit duplicate-adoption edge, and separate upload/finalize capability from authenticated status polling.

- **[S5-DR2-H6 HIGH] Metering still has no durable reservation state and its timing is impossible.** §3.6 says reservation occurs pre-spool yet uses deterministic PDF page count, which is unavailable until bytes have been read ([§3.6](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-migration-0007-design.md:164>)). Fix: define a reservation table with amount/state/lease/intake/task links; reserve a conservative declared cap pre-spool, resize from trusted post-scan counts, then settle/refund under the same locked state machine.

- **[S5-DR2-H7 HIGH] Matcher dead-letter/redrive semantics are not generalizable from the router.** Current redrive always re-runs taxonomy/wake projection, and readiness reports only aggregate dead letters—not per-consumer lag ([§4.4](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:242>), [router redrive](</C:/Users/zhant/Desktop/clara-rebuild/packages/runtime/lib/relay.mjs:436>), [readiness](</C:/Users/zhant/Desktop/clara-rebuild/packages/runtime/lib/health.mjs:77>)). Fix: specify per-consumer handler dispatch, atomic checkpoint/effect rules, retry threshold/backoff, consumer-specific redrive, dead letters and lag thresholds.

Fix: publish an exhaustive status matrix—book-effect reads exclude, history reads include, lines freeze for approved/withdrawn.
