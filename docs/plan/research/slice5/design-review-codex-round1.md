Verdict: **FLAWED**

1. **[S5-DR-C1 CRITICAL] DD-1 leaves a verified-intake bypass open.** The contract removes only `wake_ingest_document` from the allowlist and then claims every new document is verified ([contract §3.1](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:207>)). But `ingest_document` remains granted to every authenticated bookkeeper ([0004](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0004_governed_fns.sql:766>)) and its current body still accepts caller-supplied SHA/path and inserts the document ([0005](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0005_event_spine.sql:753>)). Fix: revoke both legacy ingest entry points, remove the allowlist row, and replace callable legacy bodies with a deterministic “use verified intake” error. The finalizer must be the sole document-creation grant.

2. **[S5-DR-C2 CRITICAL] The legacy backfill can manufacture authorizing “human” resolutions from agent/claim-only data.** §3.0 backfills every non-null `documents.client_id` as `method='human'` attributed to `uploaded_by`, while explicitly retaining claim-only rows with `bytes_verified_at IS NULL` ([contract](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:173>)). Existing wake ingest stamps `uploaded_by` as the global agent ([0004](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0004_governed_fns.sql:642>), [0005](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0005_event_spine.sql:777>)); the current gate accepts any `method='human'` row without proving `resolved_by` is human ([0004](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0004_governed_fns.sql:88>)). That converts legacy guesses into posting authority, and the proposed provenance predicate does not require verified bytes. Fix: reuse only existing qualifying human/rule resolutions; migrate wake/unknown attribution into a non-authorizing legacy candidate/unassigned state; require `bytes_verified_at IS NOT NULL` for new drafts/approvals; promote legacy rows only after verified re-upload. Preserve arbitrary legacy storage paths separately—the existing API accepted any path ([rig fixture](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/tests/rig-fixtures.mjs:85>)).

3. **[S5-DR-C3 CRITICAL] Active-filing provenance is incompatible with the deferred provenance trigger and the atomic correction transaction.** The contract requires the belt trigger to validate an active filing ([§3.1](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:204>)), while correction updates originals, withdraws drafts, then retires that filing in the same transaction ([§3.5](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:258>)). The belt is `DEFERRABLE INITIALLY DEFERRED` and fires on every entry update ([0003](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0003_books_core.sql:485>)); at commit it will see the filing retired and reject the transaction. Fix: bind entries to a specific `filing_id`; require activity in a non-deferred admission/approval guard, while the historical belt validates document/SHA/client against that filing regardless of later retirement. Alternatively force the constraint before retirement and explicitly prove the resulting historical semantics.

4. **[S5-DR-C4 CRITICAL] OCR enqueue is not durable, deduplicated, or configuration-snapshotted.** Finalization commits, then the route starts `documentIngest_v1` ([§4.1](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:300>)); a crash between those actions leaves a permanent pending document with no run. Two same-SHA intakes can both adopt/finalize and both call Azure. The contract also says engine configuration is snapshotted per task, yet defines no processing task and omits engine/version from workflow input ([§4.2](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:315>)). Slice 4 solved the same window with a durable queued task plus reconciler re-enqueue ([chat route](</C:/Users/zhant/Desktop/clara-rebuild/packages/runtime/src/chatRoutes.ts:132>)). Fix: create a task row in the finalizer transaction, unique on `(document_id, engine_id, version_n)`, snapshot engine/config and vendor-operation state there, pass only `task_id`, self-claim the run, and reconcile unbound tasks.

5. **[S5-DR-C5 CRITICAL] The OCR egress gate is weaker than binding C6 law.** S5-R1 requires a processor-disclosure clause but omits specific client authorization, short vendor retention, tested deletion, and field minimization ([contract](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:20>)). PRD invariant 16 and ADR-011 require all of those and say a DPA alone does not authorize disclosure ([PRD](</C:/Users/zhant/Desktop/clara-rebuild/docs/prd/PRD.md:129>), [ADR-011](</C:/Users/zhant/Desktop/clara-rebuild/docs/PROJECTLOG.md:54>)). Fix: make the flag gate require evidenced specific MIA client authority, DPA, cross-border basis, minimized fields, configured retention, and a tested deletion procedure. Test adapters—not generic local/dev mode—are the only permissible bypass.

6. **[S5-DR-H1 HIGH] `chatTurn_v1` silently discards attachments.** §4.5 says the frozen v1 workflow treats the part as inert but still lets Clara see document metadata ([contract](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:343>)). As built, transcript conversion retains only text and clarify parts; every attachment becomes an empty string ([chatTurn implementation](</C:/Users/zhant/Desktop/clara-rebuild/packages/runtime/workflows/chatTurn.impl.ts:323>)). Context is loaded only for a client-bound session and offers no document-by-id tool ([same file](</C:/Users/zhant/Desktop/clara-rebuild/packages/runtime/workflows/chatTurn.impl.ts:161>)); an unassigned attachment is invisible. Fix: ship frozen `chatTurn_v2` with validated attachment metadata and a firm-scoped document read tool, or remove the claim that chat attachments are usable by Clara.

7. **[S5-DR-H2 HIGH] DD-2 does not fit the as-built relay, and taxonomy v2 still creates one held task per document.** The relay has one logical consumer, `router`; `ignore` merely advances its checkpoint with no callback ([relay](</C:/Users/zhant/Desktop/clara-rebuild/packages/runtime/lib/relay.mjs:34>), [batch path](</C:/Users/zhant/Desktop/clara-rebuild/packages/runtime/lib/relay.mjs:327>)). Meanwhile the contract keeps `document.ingested → background_review` while claiming no held task per document ([contract](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:278>)); Slice 4 drains every background-review intent into held task/outbox rows ([drain](</C:/Users/zhant/Desktop/clara-rebuild/packages/runtime/lib/drain.mjs:13>)). Fix: route `document.ingested` to `context_update`/`ignore`, and define a separate matcher consumer with its own leader key, checkpoint, atomic attempt writes, retry/dead-letter lifecycle and health signal.

8. **[S5-DR-H3 HIGH] Dropping `documents.client_id` misses an as-built trigger dependency.** §3.0 names the immutable trigger, index and context pack, while §3.1 names provenance ([contract](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:173>)). It omits `_tf_validate_domain_event`, which still reads `d.client_id` for every event carrying a document reference ([0005](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0005_event_spine.sql:190>)). After the drop, document event emission fails at runtime. Fix: replace that trigger before dropping the column and validate event client/document congruence through a referenced filing; preferably add a stamped `filing_id` event reference.

9. **[S5-DR-H4 HIGH] Intake authorization and token semantics are unspecified.** Only intake creation mentions `authz`; PUT/finalize/GET do not define JWT or object-level checks, while the schema has no token hash, expiry or use state ([§3.2](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:213>), [§4.1](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:300>)). `authenticate()` merely resolves live membership and returns the role; session access is a separate mandatory predicate ([authz](</C:/Users/zhant/Desktop/clara-rebuild/packages/runtime/lib/authz.mjs:146>), [session predicate](</C:/Users/zhant/Desktop/clara-rebuild/packages/runtime/lib/authz.mjs:180>)). Fix: require bookkeeper+ on every mutating endpoint, enforce intake firm/uploader ownership, require an accessible same-firm session for `origin='chat'`, store only a hashed expiring intake token, and make GET/PUT/finalize non-oracular.

10. **[S5-DR-H5 HIGH] The intake state machine has no structural transition or concurrency contract.** The status list does not define legal edges, immutable fields, concurrent PUT exclusion, double-finalize behavior, or ownership of `op_key` ([contract §3.2](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:213>)). Two PUTs can race over one spool, and a caller can retry finalization under a new operation key. Fix: add DB transition/CAS triggers, immutable firm/uploader/origin identity, a unique fixed op key, one upload lease with expiry, compare-and-set finalization, and exact replay receipts for every terminal state.

11. **[S5-DR-H6 HIGH] Tenant congruence and FORCE-RLS are not designed for most new tables.** Only `document_filings` explicitly says FORCE RLS. Extractions, regions, attempts, candidates and correction items omit `firm_id`; `client_identifiers(firm_id, client_id, …)` has no structural same-firm constraint; candidate `region_refs` is unvalidated JSON ([§3.3–3.5](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:227>)). The existing house rule stamps `firm_id` on every firm table rather than trusting callers ([0003](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0003_books_core.sql:25>)). Fix: carry and stamp immutable `firm_id` throughout, add composite parent/firm constraints or validation triggers, normalize candidate-region references, FORCE RLS on every new table, and specify exact human/agent/runtime grants.

12. **[S5-DR-H7 HIGH] Draft withdrawal is impossible against the as-built journal schema, and the new lock order is undefined.** Correction requires drafts to become withdrawn ([contract](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:96>)), but journal status permits only `draft|approved` and the immutability trigger rejects every other transition ([0003 table](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0003_books_core.sql:101>), [trigger](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0003_books_core.sql:349>)). “Deterministic lock order” also fails to state how filing locks compose with the existing original-before-mirror order ([0005](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0005_event_spine.sql:846>)). Fix: define `withdrawn` plus actor/reason/time and all dependent predicates; publish one exact global lock order covering filings, originals, mirrors and unique slots, then retrofit draft/approve/reverse/correction writers.

13. **[S5-DR-H8 HIGH] Pages/day and OCR concurrency cannot be fail-closed with only begin/settle.** The contract promises atomic pages/day admission before page count is known, then records actual pages only at settlement ([§3.6](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:272>)). Concurrent in-flight jobs can all pass the same remaining balance; crashes can leak concurrency indefinitely; abandoned and duplicate intakes have undefined charging. Fix: deterministically preflight page/frame counts or reserve a conservative maximum, persist reservation rows, settle/refund idempotently on every terminal path, make adopted duplicates share one charge/task, and reclaim expired concurrency leases.

14. **[S5-DR-H9 HIGH] The retention design permanently traps unassigned documents at the far-future value.** It sets a far-future unassigned floor while separately forbidding any shortening ([S5-R9](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:58>), [§4.7](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:362>)); filing can therefore never replace that sentinel with a finite date. Multi-client filings also leave the controlling client/FY undefined, and the contract calls §7a complete while deferring close recomputation ([follow-up](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:463>)). Fix: represent unassigned retention as a separate hold/effective-infinity state, initialize the statutory floor only on filing, take the maximum across all applicable filings, and keep legal hold independent.

15. **[S5-DR-H10 HIGH] Malware and archive-bomb handling was dropped from the ratified evidence.** Runtime design performs size/type sniffing but no malware scan or quarantine ([§4.1](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:300>)); the archived transport verdict explicitly required a locally controlled scan before canonical upload/Azure and decompression limits ([evidence](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/research/slice5/transport-codex-verdict.md:64>)). With delete-never storage, a malicious Office/PDF object becomes permanent and potentially downloadable. Fix: scan before canonical custody, bound ZIP entries/ratio/uncompressed bytes and XML entities, add `malware_detected/quarantined` states, prohibit OCR/download, keep signatures fresh, and unlink successful spools immediately.

16. **[S5-DR-M1 MED] Structured parsing has neither an event nor a usable source-location model.** §4.4 consumes “OCR/parse events,” but taxonomy defines only OCR completion/failure ([contract taxonomy](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:278>), [matcher](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:333>)). `document_regions(page_n, polygon)` cannot cite XLSX cells, CSV rows or DOCX paragraphs ([§3.3](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:227>)). Fix: emit vendor-neutral `document.extraction_completed/failed` events for both lanes and model source locators as a tagged union: page/polygon, sheet/cell-range, row/column, or paragraph/run.

17. **[S5-DR-M2 MED] Attribution cannot be built from the specified schema and is not replay-idempotent.** Runtime design queries an alias registry, but migration design creates none; the as-built client table contains only `name` ([contract](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:333>), [0003 clients](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0003_books_core.sql:34>)). `record_rule_resolution(p_document)` also omits the mandatory stable operation key, while `client_resolutions` has no dedupe constraint. Fix: define versioned client aliases and their writer/event, candidate confirm/dismiss writers, and a stable `(document, matcher_version, input_fingerprint)` operation identity. Allow ambiguous hard identifiers to be represented and abstained—not rejected by a uniqueness constraint that hides the conflict.

18. **[S5-DR-M3 MED] `activate_taxonomy_version(v)` cannot satisfy the contract’s universal audit/idempotency rule.** The contract requires every writer to use `audit_log` and firm-scoped `op_receipts`, then introduces a global operator writer with no firm or operation key ([house rule](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:165>), [taxonomy](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:278>)). Both existing stores require non-null `firm_id` ([0002](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0002_foundation.sql:276>), [op receipts](</C:/Users/zhant/Desktop/clara-rebuild/packages/db/migrations/0002_foundation.sql:295>)). Fix: add a global operator receipt/audit surface, or explicitly make activation migration-only and exempt it; lock the catalog, prove full coverage, repoint once, and test mid-drain version stamping.

19. **[S5-DR-M4 MED] The “scoped storage credential” is not an implementable credential contract yet.** Supabase bucket scoping requires a custom Postgres role, Storage RLS policies and a JWT assuming that role; secret/service keys bypass RLS entirely ([Supabase access control](https://supabase.com/docs/guides/storage/security/access-control), [custom roles](https://supabase.com/docs/guides/storage/schema/custom-roles)). The contract names only a URL plus credential and incorrectly says no principal “anywhere” has update/delete, ignoring platform/admin break-glass authority ([§3.8](</C:/Users/zhant/Desktop/clara-rebuild/docs/plan/slice5-document-pipeline-contract.md:288>)). Fix: specify the custom role/JWT issuance and rotation, exact bucket/path INSERT+SELECT policies, zero update/delete grants, credential-expiry behavior and a rig matrix; narrow the absolute claim to routine application principals.
