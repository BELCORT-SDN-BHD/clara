# Gap map — #625 完成邀请、加入、改权及移除成员的完整流程

_Final, reconciled against two adversarial reviews (citation lens + design/safety lens), 2026-09-15, main @ 4464e471. Every path:line below was opened in this session. No command was run: nothing here is a green-run claim._

## 大白话

这张票要的是一条从**发邀请 → 接受 → 进事务所 → 改权限 / 撤邀请 / 移除成员**的完整可信流程。

**今天数据库那层其实已经做完了。** 邀请表、四扇门（invite / accept / revoke / claim）、三张读视图在 0141 落地；0145 加了"不能授予高于自己的角色"这道天花板；0147 把令牌改成只存哈希；0157 又补上"下级不能动上级""不能动自己""先鉴权后去重"三堵墙，并且有真 Postgres、真最小权限角色的电池和一个双会话竞态用例。网页端 `/settings/members` 与 `/invite/[token]` 两个面也都在，按角色隐藏控件、拒绝原文照登、每次操作后强制重读。

**差的是四块。** 一、受邀人在进工作台之前看不到"我加入的是哪家事务所、什么角色"——接受成功后直接 `router.replace('/')`，刚读到的 `firm_name` 和 `role` 被丢掉。二、拒绝信息只出现在弹窗背后的页面横幅里；弹窗自己明明声明了 `refusal` 插槽，却没人传值。三、"重发邀请"和"容量拒绝"这两个验收词在本仓库里**根本没有对应机制**，而且都是被**有意否决**的：重发因为明文令牌按 裁-16a 永不落盘（改都改不出来），席位容量则被 `docs/PRD.md:126` 明确推到"已接受、留待以后"、被 `CONTEXT.md:205` 明确写成"_Avoid_"。四、验证不够——没有任何 Playwright 走查真的把"发邀请 / 撤邀请 / 改角色 / 移除"跑到结果，成员页也没有 320px 与 200% 缩放那条腿。

**另外有一条被复核翻掉的旧结论要纠正：** 成员门的**锁顺序是别的迁移依赖的不变量**。0194 把记账核心改成先取 `clara.firms ... for key share`，正是因为 `set_member_role` 先取 `for update` 再改会员行，两个顺序在 rig 上真的撞出过 40P01。那个核心已经被 0194 和 0195 用 sha256 钉死。所以原图里"成员门与锁顺序无关"这句话是**错的**，必须替换掉，不能抄进票里。

**还有一条被翻掉的：** 活动流那个"权限变更被归错成 documents"的档位，活体身体在 **0184**（`list_activity` 在 0184:1915、阶梯在 :2078；`get_activity_event` 在 0184:2248、阶梯在 :2320），**不是** 0183:683；而且是**两扇门**，`af.15` 还断言两扇门的 kind 必须一致。0184:87-90 自己写了规矩：必须从**已安装**的身体派生、在 prestate 里 sha 钉住；0184:88-90 更直说"两条 lane 同时发同一个函数的两份身体，是一次会静默错解的合并"。这件事横跨 #633 / #650 / #647 三票——**本波次不该由 #625 来动它**。
