## Practical handoff

1. Implement reference patterns by journey slice, not by copying whole vendor pages: document source+facts, report parameter+artifact, and account search+governed detail.
2. Keep primary actions visible. Dropdown Menu holds secondary row actions; Sheet holds supporting context; Dialog holds one focused edit; Alert Dialog is reserved for a consequential destructive action. Durable accounting state remains inline and in Work/Activity rather than living only in Toast.
3. Every slice still needs Clara-specific empty, no-results, no-permission, stale, partial, retry/idempotent, narrow, 200% zoom, keyboard/focus, reduced-motion and live-permission acceptance. The frames above provide no evidence for those conditions.
4. Unobserved reference states are posted-document correction and impact, report queue/failure/reproducibility/history, COA edit/control-account impact/history, and Knowledge fact/identity/version correction. The [Clara interaction contract](refresh-2026-09-08-frontend-interaction-contract.md) defines these from accepted product and backend requirements. Their implementation/prototype proof belongs to the owning slices; lack of a vendor screenshot alone does not require endless research or justify inventing observed behaviour.
