## TA-P1 · 名册补白：法 71「恰好」清单没点名的动作归谁

**RULED 2026-08-22: C — 开放名册。** 法 71 没有明文保留的动作一律归 Clara；七项保留动作原样不动。
riders（wake 兄弟动词 · 能力出厂默认开 · 60 天宽免掣配一道机械重复付款墙）与 orchestrator 的
A（两问判定规则）异议，见 `docs/adr/0074-the-track-a-sitting.md` TA-P1。

**阻塞** · 22 个成员 · 解锁 F-A3 · F-A4 · F-A5 · F-A6 · F-A7

法 71 列了一张「仍归人手」的清单，并且用了「恰好」两个字：年结钥匙②③、把银行行剔出
对帐、期初种子批准、法定措辞、`canonical` 定义、能力授予、e-filing。问题是：帐上还有
几十个动作**两边都没点名**——把银行月结单入册、签一张「本月已对平」的核证、拆掉一个配
错的配对、新增一个银行户口、铸一张报表快照、发布一个报表模板、让一个旧指标定义退役、
重新排一次渲染、开一个新会计年度、自己开一个客户档案……今天它们都是人手，因为当初写
的时候只有人。您现在要给的不是一个个的答案，而是**一条判定规则**：清单没点名的动作，
默认归谁？

- **A ★ 两问判定规则（可逆性 + 消失性）。** 对每一个未点名的动作问两句：**(i)** 它会不会
  让帐上一笔差额、一项义务、或一个已经具名的问题**消失**，或者让一份带事务所名义的东西
  **对外生效**（一张证明、一个发布的模板、一份签发的报表包）？**(ii)** 它是不是**结构上
  不可逆**（字节已送出、永久行已铸、人的签字被作废）？**任一为「是」→ 留人；两个都
  「否」→ Clara 按法 71 的姿态持有。** 同一条规则也管**宽免掣**（ack 旗标），不只管动词。
  附带两条同源规定：新授权一律以 **wake 兄弟动词**新增（只扩不弱），**永不改写活体人手
  函数**；新能力**出厂默认开**，不设逐所旋钮（ADR-0072② 已拒绝按所的旋钮），刹车是动作
  自身的可逆性，不是一道签字。
- **B 封闭名册。** 没有明文授予的一律留人，每个动词单独裁一次。
- **C 开放名册。** 没有明文保留的一律归 Clara。 ← **裁定**

**★ 推荐 A 的诚实代价**

1. 法 71 的「恰好」会从**逐项列举**变成**一条判定规则 + 列举**。这是对宪章措辞的一次
   修订，要落一条 ADR、重新签摘要；以后任何人读法 71 都要连这条规则一起读。
2. 这条规则会往人手清单里**加进**今天没人点名的几件事：作废月结单、作废对帐、处置例外
   （含冲销）、60 天陈旧未清项目的宽免掣、驳回别人写的定义草稿、登记银行户口。也就是
   「无人值守」在这几点上名不副实——真实客户帐上几乎每个月都有超过 60 天的未清项目，
   对帐会经常停在那里等人按一下。这是刻意付的：重复付款是真金白银的损失。
3. 「新授权一律用 wake 兄弟动词」会让 F-A3/F-A4/F-A5 各多一批动词、授权与名册钉（T17
   要求每条 grant 命名一个已上线的调用方），CI 里那几处封闭普查要**只扩不弱**地逐处重裁。
   好处是不用为了「加一格授权」去开 D1 停写窗口改活体。
4. 「出厂默认开」意味着一家事务所**无法**「不让 Clara 起头结账」或「不让她用自由读」。
   今天只有 BELCORT 一家在用，短期没差别；将来 SaaS 化要收回，是一次法层面的改动，不是
   一个配置开关。

## TA-P2 · 没有单据的数字凭什么进帐

**RULED 2026-08-22: A+。** 三个出身（见证读到的 · 版本化确定性求值器算出的 · 生效日期政策表的一行）；
政策表由她起草、走 **owner 一键审计门（不是 PR）**、两道机械校验、行 immutable+supersede、缺当日行一律拒绝。
`0016` 的「只能 migration 写」断言在 Tier-1 表上放宽成一支受治理动词。详见 ADR-0074 TA-P2。

**阻塞** · 8 个成员 · 解锁 F-A4 · F-A8 · F-A9 · F-T1

见证对读（法 72）管的是**单据上的**数字。可是帐上还有一大类数字没有单据可读：年结的
应计、预付、拨备、折旧补提；以及税率、门槛、汇率、模型单价这些外部/法定数字。法 71 说
「判断即无人值守过帐权威」——这句话要不要一路管到这些**没有凭证**的数字上？

- **A ★ 三个出身。** 任何进入帐簿或正式产物的数字，只能有三个出身：**(1)** 见证对读读到
  的单据数字；**(2)** 一个**版本化确定性求值器**从帐上已有数据重算出来的数字（按已过帐
  固定资产表算折旧、按已过帐预付发票摊销、模型花费 = token × 版本化单价）；**(3)** 一张
  **生效日期政策表**的某一行（SST 税率/门槛、BNM 汇率、模型价目）。三者皆无 → **出草稿
  等人**，Clara 诚实说「我算不了」。政策表另有三条同源规定：行**不可原地改，只能
  supersede**；查不到当日的行**一律 fail-closed**（绝不把上一行顺延顶上）；法定表的行仍由
  **人手 PR / migration** 落地，定时抓取只负责**起草与比对**并开一条待答问题。
- **B 判断即数字。** 法 71 一视同仁：没有单据的数字也由 Clara 判断入帐；定时抓取直接写
  政策表；缺当日行时按最近一行顺延。
- **C 全部草稿。** 没有单据的数字一律只出草稿等人批，政策表全人手、无抓取。

**A+ 是裁定的形状**：A 的三个出身原样成立，但第三条的落地门从「人手 PR / migration」改成
**一支受治理的 owner 一键动词**（两道机械校验：两个独立官方来源一致、数值落在合理带内）。
owner 起先偏向 B（「只要 context 对，Clara 可以自己算」）；B 的计算半边本来就等于 A，B 的
估计半边与顺延会修宪（法 1 / PRD §6 / 硬约束 2），因此改取 A+。宪法不动。

**★ 推荐 A 的诚实代价**

1. **SST / 法定这一半的「自动化」缩水成「自动起草」**：每次 RMCD 或 LHDN 调税率，仍要人
   手开一次 PR、走一次完整评审梯，跟今天几乎一样累。换来的是 migration 0016 那条「这张表
   只能靠 migration 写」的结构墙一个字不动——而这堵墙正是「同一天每个客户看到同一个

## TA-P3 · 外送治理：新一类模型处理怎么取得授权

**RULED 2026-08-22: A。** 一类处理 = 一个具名用途、逐客户开户时一次签齐；结构上没有客户的两刻由
BELCORT 签一条**所级窄用途**并用输出限制锁死（只准出归属判断/表单建议，封闭可收清单，身份证拒收）；
不带身份的法规查询不算披露；`classify` 纳管。**C6 清单升为关键路径。** 详见 ADR-0074 TA-P3。

**阻塞** · 9 个成员 · 解锁 F-A3 · F-A7 · F-A8

今天「客户资料送出去给模型看」是逐客户签一份授权、按用途具名（`wiki_synthesis` /
`statement_extraction` / `witness_extraction`）。Wave F 一次冒出五类新的送出去：银行配对
（整本流水 + 往来户名字）、归户判断（**还不知道是谁**的单据）、开户访谈时人当场递进来的
证书、上网查法规、以及一份同时属于买卖双方的单据。其中归户是一个**死结**：要判断这份
单据属于谁就得先看它，可是规矩是送出去之前必须已经知道是哪个客户、而且那个客户签过
授权。您要给的是一条通用规矩：**一类新的模型处理，怎样才算取得了授权？**

- **A ★ 一类处理 = 一个具名用途；结构上不可能有客户的那一刻，用一条「所级窄用途」顶，
  并用输出限制锁死。** (1) 凡能确定客户的处理，一律新增具名用途、逐客户 owner 签署 +
  启用，没签的整条 lane **停着**（fail-closed，不偷偷降级）；(2) 归户前 / 开户中这两刻

  归属判断或一格表单建议，不准落任何会计事实、不准落金额**，可递进来的文件是一张**封闭

## TA-P4 · 收据与「人点过头」的证据强度

**RULED 2026-08-22: A。** 收据纪律延伸到每一个代理判断动作；who/why/from-where 机械绑定到触发动作；
读与收据同一事务（DEFINER 读包装器）；bookkeeper+ 人用读面；fetch 工具自铸引用行，零引用的收据拒绝。
人点头 = 一次明确「已复核」+ 收据记作者=Clara / 是否原样采纳。详见 ADR-0074 TA-P4。

**阻塞** · 8 个成员 · 解锁 F-A4 · F-A5 · F-A6 · F-A8

法 71 只对**过帐**这条 lane 写明了收据要带 model + version + rationale。Wave F 会新增一批
**不是过帐**的判断动作：冻结一个年度、跑一份报表包、读一段自由 SQL、上网查一条法规、
替人起草一段声明。这些动作今天要么没有收据，要么收据里最关键的那一栏（为什么读、是谁
的意思、内容从哪来）**是模型自己写的一句话**。同一个问题的另一面：当 Clara 起草、人点
头，收据要留下什么，那个「点头」才站得住？

- **A ★ 收据要机械绑定，而且要有人能读。** (1) 法 71 的收据纪律**延伸到每一个代理判断
  动作**（冻结、报表、读、上网），带 model + version + rationale，`via_wake_kind` 不再
  硬写 NULL；(2) 收据里指认「谁 / 为什么 / 从哪来」的栏位必须**机械绑定到触发它的那一次
  动作**（chat turn / wake task / fetch 调用），模型写的话只能是附加说明，不能是唯一
  证据；(3) **写不出收据就不准跑**——读与收据在同一个事务，一份没有收据的读在结构上不
  可能发生（这指向一支 DEFINER 读包装器，而不是裸连接上的 SQL；它仍可接受 SQL 文本作
  参数，与「自由读」的形态不冲突）；(4) 收据要**有人能读**：按现有 `audit_log` 的
  bookkeeper+ 楼层开一个人用读面。人点头这一半：一次明确的「我已复核」动作 + 收据如实
  记下**文字作者是 Clara、是否原样采纳**；批量回显可以，但少数「一错全歪」的项目仍逐格。 ← **裁定**
- **B 尽力而为。** 收据维持现状：purpose 由模型自填、读与收据分两个事务、没有人用读面、
  close/report 侧不加栏位；人可以直接原样提交，不留作者痕迹。
- **C 最严。** 收据机制同 A，但人这一边必须**自己重打或实质改过**才算签，且一律逐格确认。

**★ 推荐 A 的诚实代价**

1. **最贵的是第 (3) 条**：F-A6 的读要走一支 DEFINER 包装器，而不是「拿个只读连接直接
   跑」，多一层设计，也把 law-28 对抗审查的重点从「语法有没有被堵死」移到「读到了什么、
   有没有被收据记下来」。
2. **close 侧与 report 侧要加栏位**，`finalize_close` 这个活体要动——而 Track B 的
   task #17 Fix A 要改的是**同一个函数体**，两条线必须合并成一次迁移或严格排序，并占一次
   D1 停写窗口。
3. **F-A8 的引用纪律要做成工具边界的机制**：fetch 工具自己铸一条引用行，凡调用过工具却
   零引用行的收据一律拒绝。这是唯一能让「每条网上得来的依据都要注明出处」变成可执行的
   做法；否则它只是提示词里的一句叮嘱，而硬约束 2 要求「执行是结构性的，不是提示词级」。
4. **人这一边每次多点一下**，而且要接受一个不好看的事实：一个人面对 17 条回显清单，很
   可能扫一眼就说「对」。所以关键项仍要逐格——开户访谈不会像想象中那样「一句话搞定」。

## TA-P5 · 日历唤醒：Clara 可不可以按钟自己动手

**RULED 2026-08-22: A（原则形式）。** 系统新增**一个**时间触发唤醒源，醒来后做的事一律归法 71
（不设 ramp / 不设首发草稿 / 不抽样）+ 数据闸门 + 收据。**法 21 按 owner 原话收窄为「按周期过帐的带子」。**
新的按钟动作只需一个设计单元，不需要新裁定。详见 ADR-0074 TA-P5。

**阻塞** · 4 个成员 · 解锁 F-A3 · F-A4 · F-A5 · F-A8

今天系统里**没有任何东西会按日期自己醒来**——每一次唤醒都是某份单据进来触发的。可是
Wave F 有三处天然要按钟走：月底自己把银行对帐做完、到了年结日自己开始准备关帐、每月
自己出一份管理帐。旁边还有一条 ADR-0071 明写「今晚没有碰」的旧法（法 21 的日历带子
主义：admin 先签一次授权、第一次触发只出草稿、逐步放开）。这几条 lane 归哪条法管？

- **A ★ 有钟，归法 71。** F-A4 铸一个**时间触发的唤醒来源**，并在 ADR 里明说这是产品里
  第一条按日历自己动的道；它按法 71 的姿态跑：不设 ramp、不设首发草稿、不抽样。法 21 的
  射程**明文收窄**为「按周期**过帐**的带子」（折旧、经常性分录）——它管的是过帐，不管
  生命周期动作。这句话要由您说出口，否则将来会被读成绕过法 21。理由：法 75 自己就写着
  Tier-1 是「scheduled fetches」，现行法已经预设了定时道的存在；而 B 会把 G1.2/G1.3 已经
  否决过的 ramp 从后门放回来。 ← **裁定**
- **B 归法 21。** 凡时钟触发的动作，每客户先要 admin 签一次授权，且第一次触发只出草稿。
- **C 没有钟。** 每一个代理动作都必须由事件触发（单据入册、分录过帐、人开口）。

**★ 推荐 A 的诚实代价**

1. **月底 Clara 会在没有人看着的时候把对帐做完、把调整入帐、把年度冻上。** 这本来就是
   G1.2/G1.3 选定的姿态，但银行/年结是第一条会按日历自己动的道，所以要明确说出来而不是
   默默继承——设计里必须配一条显眼的通知和一个人随时能按的「先别关」。
2. **要铸第四种（或第五种）wake kind**，两处 CHECK 与六个名册面要跟着扩。F-A2 的 D34 刚
   做过一次，有先例可循，但仍是一次活表 CHECK 更换。
3. **会出现「没人要过」的产物**：自跑的报表包会产生已封存数据集与渲染任务，`clara-render`
   按小时计费、`reports/` 桶只增不减，存储会一直长。而且必须明写：0084 那套「孤儿草稿只
   能被人领养」**不套用到报表 run 上**，否则自跑的包会永远卡在等人领养。

**触及的法/裁定**：法 21（WD-R5/R8 日历带子主义，0071 明写 NOT REACHED）· 法 71
（G1.2/G1.3：永不 ramp / 永不抽样 / 永不暗启）· 法 75（Tier-1 的 scheduled fetches）·
法 68（ARM-0，NULL 主体自成第一分支）· 法 69（领养语义）· PRD 不变量 2(c)/11（proactive
只说不做）· 房规 11（碰撞交 owner）。
