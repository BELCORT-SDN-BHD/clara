A Malaysian e-invoice whose only identifier is a TIN therefore leaves as `party_unresolved` even when `clara.counterparties.tin` holds it. Fix round 1 made the contract honest (the schema description and 0225's resolver header now say which keys resolve); the precedence question — which wins when registration and TIN disagree, and whether a cross-client identifier (0215:1157-1164 reads `tin` only as an identity WATCH) may resolve inside one client's books — is a ruling, not a hunk.
