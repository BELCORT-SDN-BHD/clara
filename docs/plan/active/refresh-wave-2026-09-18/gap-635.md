## 大白话

这张票要做的是：事务所的老板/管理员点开「设置 → 事务所」的时候，看到的是**真话**——我们所现在到底
处在什么状态：法律条款是哪一版、谁在什么时候点了同意、Clara 现在到底被授权替客户做账没有、这个月
Clara 替我们烧了多少模型调用、我们所能上传多少份文件、我们是不是还在 beta（没有付费、没有账单）。

今天点进 `/settings/firm` 只有**两段字**：一段讲「审批门槛控件已经取消」，一段讲「签署能力没有界面」
（`apps/web/components/firm-admin/settings-panel.tsx:61-90`）。设置首页底下还挂着一句
「用量、套餐、账单都还没有」（`apps/web/messages/en.json:375`）——这句话**今天是真的**，而这张票就是把它
变成假话、然后把它换掉。

最要紧的一件事，今天是个**真窟窿**，不是「还没做」而是「做了一半会出事」：Clara 替客户做账的**权限**
是从事务所接受的 Terms + DPA **推导**出来的（`0195_work_egress_purpose_and_execution_trace.sql:875-909`，
架构 §5.E）。规矩写得很清楚：**一旦法务发布了新版本而事务所还没接受，权限当场失效，没有任何一扇门能
补救，只能去接受新版本**（`docs/ARCHITECTURE.md:402-403`）。可是**接受条款的界面只存在于注册流程里**
（`apps/web/components/entry/signup-legal-stage.tsx:13,20`）。也就是说：法务哪天发 v2，全所的 Clara
当场停摆，而已经进了工作台的老板**在产品里找不到任何一个地方可以点「我接受」**。Work 详情页的文案已经
在叫人去做这件事了——「An owner can restore it by accepting the current Terms and Data Processing
Agreement」（`en.json` → `WorkDetail.egressNotAuthorized.body`）——**但没有链接可去**。

举个具体的：E2E Accounting 的老板 owner@example.test 早上发现三条 Work 全部 refused，代码写着
`egress_not_authorized`。原因是昨晚法务把 DPA 发到了 v2。他要做的只有一件事：去设置里点一下「接受
DPA v2」。**今天他做不到。**

**第二个真窟窿，是这一轮评审逼出来的**：查「本所这个月烧了多少模型钱」的那扇门
（`clara.get_llm_usage_summary`，`0110_f_a9_llm_usage_reshape.sql:706-756`）**今天没有任何职级墙**——
它只问「你查的是不是你自己所」，不问「你是不是管理员」。所以一个**只读的 viewer**（比如一个实习生）
今天就能把全所的模型花费读出来。它今天没出事，只是因为**产品里根本没有人调用它**
（`grep` 过 `apps/web` 和 `packages/runtime`，零个调用方）。这张票一旦把它接到界面上，这个洞就变成活的。
所以本票**直接把这扇门重切、补上 admin 墙**，而不是在旁边另开一扇有墙的门、把没墙的那扇留着装作没看见。
代价已经量过：库里现有的用量测试全部用的是**所主（owner）身份**（alice / dave / erin，
`rig-fixtures.mjs:421`），补墙一个格子都不会红。

剩下的三件是「如实展示」，不是「新建功能」：

1. **套餐**：库里就一行，`clara-beta-2026 / Clara Beta / 0 分 / MYR`，而且带着一列
   `amounts_ruled = false`（`0163_checkout_gate_c3_folded_door.sql:196-215`）——**数据库自己在说「这个价
   还没有业主裁定」**。所以界面上永远不准出现一个价钱，只能写「beta，未定价」。
2. **账单/发票**：整个库里**没有任何一张发票表**。有的只是一行付款证据
   （`firm_registration_payments`，`0163:219`），而且它**只有 operator 能读**（`0188:304`），事务所自己
   读不到。所以这一格是「解释 + 支持入口」，不是一个假的「管理账单」按钮。
3. **用量**：真的有——按月、按调用种类、带 token 数、带「有几笔没有价格」的覆盖率提示。**但它的价钱是
   美元**（`llm_price_table.currency` 被 CHECK 钉死成 `'USD'`，`0110:497`），而所有客户的账簿是马币。
   所以只能标成「供应商计价（美元），不是贵所账簿上的钱」，绝不换算。用量表**可以导出成 CSV**：那些行
   本来就已经在浏览器里了，导出用的是本仓库已有的保存机制（`lib/download-mechanism.ts:53`），不新开路由、
   不新开门。

**硬话（需要业主拍板的只有定价/供应商，别的我都能从库里查出来）**：C-01 / C-56 说定价、花费、供应商
选择必须业主明确决定，不能由实现默认（`612` 附录 A.2 第 13、68 行）。这张票**一个价都不发明**。

## Questions

*(Only questions whose answer changes what gets built. One recommendation each.)*

**Q1 · 事务所自己的设置页要不要显示 Stripe 的客户号/订阅号？**
- **今天**：这两列存在（`0163:225-226`），但整个产品里只有 operator 的支持台读得到（`0188:304`）。事务所
  自己看不到，也没有任何按钮能拿它做事。
- **裁定建议**：**不显示**。只显示「有/没有付款记录」「有/没有订阅」加日期。理由有两条：一是这两个 id
  对事务所**没有任何可执行的动作**——没有 billing portal、没有取消、没有换卡；二是把一个活的供应商对象 id
  放进浏览器，等于给一个我们不需要的外发面开口，而 0164 已经为同类理由拒绝把金额送上线
  （`0164:120-121`：「a money figure that crosses a wire nobody reads is a figure a later lane will render」）。
- **另一选项的代价**：显示了，就必须同时回答「点它能干嘛」，否则是一个假控件；而真正能干的事（portal）
  需要一条新的 Stripe 集成，那是另一张票。
- Code: `firm_registration_payments.stripe_customer_id` / `.stripe_subscription_id`;
  `clara.get_firm_commercial_state` 的 `payment` 对象。

**Q2 · AI 用量的「钱」用什么单位显示，月份按哪个时区切？**
- **今天**：`llm_price_table.currency` 被 CHECK 钉死成 `'USD'`（`0110:497`），而账簿是马币且 FX 是明确的
  非目标（`0110:494-496`）。月份窗口是 `date_trunc('month')`（`0110:711-712`）配
  `(created_at at time zone 'utc')::date`（`0110:750`），**不是** `Asia/Kuala_Lumpur`。
- **裁定建议**：**token 数和调用次数永远显示；美元金额显示但明确标注「供应商计价（USD），非贵所账簿金额」，
  绝不换算**；月份**按门返回的 UTC 窗口如实标注起止日期**，不要在界面上写「9 月」却给一个偏移半天的区间。
  导出的 CSV 头两行把这两件事一起带走。
- **另一选项的代价**：换算成马币 = 在专业人士的屏幕上发明一个汇率（法 18 / P-FX 明确不做）；只显示 token
  = 业主问「这个月烧了多少钱」时产品答不出来，而数据库其实答得出。
- Code: `clara.get_firm_ai_usage` 的 `price_currency`; `lib/firm/usage-period.ts`; `lib/firm/usage-csv.ts`;

**Q3 · 「接受新版法律条款」这个控件，用什么机制只给 owner 看？**
