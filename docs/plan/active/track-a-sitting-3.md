## TA-P12 · 刹车普查：「永不设限」到底关掉哪几道闸

**RULED 2026-08-22: A。** 一次普查、一次裁定、分两批执行。**拆**：聊天每日 token 硬顶 · 无人值守
`refused_budget`（60%/100%）· 每天 15 张无人值守销售草稿的量额。**留**：并发地板（3 运行 / 2 扫描，
引擎保护）。聊天硬顶**先于 F-A9 单独热修**；无人值守那条随 F-A9 或随该 lane 退休——owner 明确接受
「这笔工可能白做」也要停掉正在违反裁定的线上行为。**收据字串更名是强制项。** 详见 ADR-0074 TA-P12。

**阻塞** · 3 个成员 · 解锁 F-A9

G8 已经裁定「只计量、永不设限，任何预算都不能暂停自动化」。可是线上今天**至少有三道闸
还在按用量拒绝**：(1) 聊天准入函数里 Slice-4 时代的「每日 token 预算硬顶」——超过当天
预设额度（默认一百万）就直接拒绝新的对话请求；(2) **无人值守那条 lane**——扫描类工作用
到当天额度的 60% 就被拒（收据写 `refused_budget`），一键类到 100%；**这一道正是 G8 字面
点名的「自动化」**，采集当初只看到第一道；(3) 一条「每天最多 15 张无人值守销售草稿」的
量额上限——它既不是引擎保护、也不是 token 预算，而是当年 7A 上线期的信任调节器。

- **A ★ 一次普查、一次裁定、分两批执行。** 把线上每一道会拒绝的闸**逐条列出并分类
  KEEP / REMOVE**：每日 token 硬顶（聊天）与 `refused_budget`（无人值守）**都拆**；每天
  15 张的销售量额上限**也拆**（它是一个会暂停自动化的额度，只是单位不是 token）；并发
  上限（同时 3 个运行、同时 2 个扫描）**保留**——它们保护的是引擎，不是钱包。执行分两
  批：聊天硬顶**先于 F-A9 单独热修**（那是已经在违反裁定的线上行为），无人值守那条随
  F-A9 一起。**附带一条必须做的更名**：今天引擎保护的拒绝与预算拒绝**共用同一个收据字串**
  `refused_budget`——预算闸拆掉之后，一次纯引擎保护的拒绝仍会在您看的收据里写着「预算
  不足」。现在改名，否则可见的记录会说谎。 ← **裁定**
- **B 只拆聊天那一道**，其余留着。
- **C 全部维持**，把 G8 读成只管未来的新闸。

**★ 推荐 A 的诚实代价**

1. **要替换两个正在使用的写入函数体**（聊天准入、无人值守准入——后者是一条六段拼接的
   活体谱系），各要一段 D1 停写窗口 + 完整评审梯。而无人值守那条 lane 本来就要在 Wave F
   内退休，**这笔工可能白做**。这是真实的取舍：现在拆，是花一笔可能作废的钱去消灭一个已
   在违反裁定的行为；等退休，是让自动化再被自己的预算暂停几周。
2. **拆掉的三道闸各有它当年的理由**：15 张/天那道是 7A 上线期刻意的信任调节器，拆了之后
   一个刚接的客户第一天就可能收到几十张无人值守草稿。您已经在 G1.2 拒绝过所有 ramp，所以
   这与您的姿态一致——但请知道它拆掉的是什么。
3. **更名会动到收据里的字串**，历史行不改（append-only），所以一段时间内收据里会有新旧
   两种写法，要在读面上说明。

**触及的法/裁定**：法 76 / G8（只计量、永不设限；引擎保护的并发地板保留）· ADR-0071
G1.2（永不 ramp）· G6（autoDraft/rule-post 执行层的退休是 Wave-F 完成条件）· 法 22
（可见记录不得说谎）· 硬约束 3（评审梯）· CI/CD 章节的停写窗口规程 · PRD §8（已按 G8
收窄；但 PRD 开放问题 3 仍写着旧的 budgets 字样，属文档陈旧，同批修）。

## TA-P13 · 计量的口径：一本帐还是两本

**RULED 2026-08-22: A。** 一本记录之帐：`llm_usage_events` 改形以装下任何调用种类（两个必填外键改可空 +
调用种类判别字段），**现在就加 `client_id` 与触发人（可留空）**——过了今天不可逆；Slice-4 旧用量帐与
预留/对帐机制在闸拆掉之后**退休（= 删除线上真实资料，owner 的这一句已记录在案）**，`firm_limits` 的
死栏位一并处置；跨事务所不建界面但底层不写死。**摘要法 76 的「LLM」是漂移，同批修。** 详见 ADR-0074 TA-P13。

**阻塞** · 4 个成员 · 解锁 F-A9 + 所有会调模型的 lane

「每月花了多少钱」这个数字要真。今天线上有**两套**计量底子：Slice-4 时代的每日/每任务
用量帐（它唯一的读者就是那几道即将被拆的闸），和 F-A1 刚建的「每次模型调用记一行」表
（只能记「读文件」这一种；聊天、记帐判断、自由查询、访谈、上网都塞不进去）。而且新表是
**append-only**——**当初没记上的维度，以后永远补不回来**：今天它没有 `client_id`，也没有
「是谁触发的」。

- **A ★ 一本帐，一次把维度定死。** (1) 新表成为**唯一的记录之帐**，结构改成能装下任何
  一种调用（现有两个必填外键改成可留空 + 一个通用的调用类型字段），以后每个新功能一律走
  同一个记录口子；(2) 旧的每日/每任务用量帐与那套预留/对帐机制在闸拆掉之后**退休**——这
  是删除线上真实数据的动作，需要您明确的一句话；`firm_limits` 里那几个已死的上限栏位一并
  处置，别留一把上了膛的枪；(3) **现在就加上 `client_id` 与触发人**两个可留空的维度——
  马来西亚事务所要按客户 on-bill，「哪个客户花了我多少模型钱」是决定这个客户赚不赚钱的
  数字，而这个决定**过了今天就是不可逆的**；(4) 跨事务所的运营视角这次**不建界面，但底层
  不写死**成只认单一事务所。 ← **裁定**
- **B 先窄后宽。** 只管「读文件」的用量，先把月度汇总做出来；聊天与以后的新功能各自上线
  时自行补记录；两本帐并存。
- **C 先窄发布 + 明记一笔已知缺口**，并定一个必须补齐的时间点。

**★ 推荐 A 的诚实代价**

1. **要求以后开发 F-A2 / F-A6 / F-A7b / F-A8 的人统一走这一个记录口子**，多一点协调成本。
2. **退休旧帐是删除真实数据**：要您点头（房规：不是代理造的东西，删除前先问），而且
   ADR-060 的数据授权是 DATA-scoped、不含 schema。
3. **多两个可留空的列 + 每个记录点做一次客户解析**（文件道可从单据推出客户，聊天道要看
   会话有没有绑客户，所以必须可留空）——便宜，但**必须在第一行生产资料写下之前**做完。
4. 不这样做的代价是**不可逆**的：这几个月的花费永远无法按客户或按人拆开，而且月度数字会
   长期性偏低（聊天大概率是调用量最大的一块），没有任何机制会提醒这个偏差。

**触及的法/裁定**：法 76 / G8 · 硬约束 2 / PRD §6.1（汇总数字必须真实、可复现）·
法 16 的类比（生效日期版本化价目表）· 不变量 (c) RLS 结构性隔离 · 法 6（append-only）·
ADR-060（数据授权 DATA-scoped，不含 schema）· 房规「删除不是自己造的东西前先问」。

|---|---|---|---|

| **F-A9-M4** 汇总的维度（*遗漏候选；过了今天不可逆*） | 现在就加 `client_id` + 触发人（皆可留空） | 不加——这几个月的资料永远不能按客户或按人拆开 | 同 B |

## TA-P14 · 一个 Wave-F 项目「做完」的定义

**RULED 2026-08-22: A —— 闭环交付。** 六条：修好自己产出所喂的闸（银行度量口径→F-A3，未编码凭证→F-A4，
第一抽屉 P-3→F-T4）· 造出自己制造的每一个人手动作的**最小门**（UI 可以简陋，不能没有）· 提议要有持久
载体 · 验收在真实帐本上做，没有的按 ADR-048 标注合成并**把顺延写进记录** · 合约 F-A5 的「端到端」改写成
open→evaluate→seal→render（签发是人的动作）· 丢失的记录视为已失。**渲染器条款：第一次真实封存 + 字节
复现演练排在 N3 之前。** 详见 ADR-0074 TA-P14。

**不阻塞（但它定的是每一项的验收条）** · 12 个成员 · 影响全部项目

这一条不改任何授权，只定一件事：**一个 Wave-F 项目交到什么程度才算做完。** 现在有一串
同形的缺口摆着——Clara 拿到年结钥匙①之后，人拿钥匙②定案关帐**实际上没有门可以走**
（整个 dashboard 与 runtime 里，定案/放弃/重开/开年度一个调用方都没有）；她「提议关帐」
这句话**没有任何载体**（现有的待答问题结构上装不下一个以年度为范围的提议）；她要读的
那几道年结闸有三道是**空绿门**（一个银行户口都没登记、帐上却有 RM 39,252.03 真实结余，
闸照样放行）；「端到端出一份报表包」的终点其实卡在签发（那是钥匙②，人的动作）；改渲染
器会让旧封存件的字节复现承诺**在从没做过一次真实演练之前**先被打破；还有两条记录（N2、
N4）**内容已经丢了**。

- **A ★ 闭环交付。** 一个项目做完的定义是：**它开启的那个回路，必须能被必须走它的人从头
  走到尾**。(1) 它**修好自己产出所要喂的那几道闸**（谁产出谁负责）；(2) 它**造出自己制造
  的那个人手动作所需要的最小门**（定案关帐、放弃结账、一张「Clara 提议关帐」的复核卡、
  签字正本的存档动词——UI 可以简陋，但不能没有）；(3) 「提议」要有**持久载体**，不是一句
  聊天话；(4) **验收在真实帐本上做**；没有真实帐本的（BEE 的 FY2025 已整体推迟到 Wave-G
  重置）在合成沙盒跑完整一轮并按 ADR-048 标注为合成，**把顺延写进记录**——是记录在案的
  顺延，不是遗漏；(5) 「端到端」在合约里**改写成 open→evaluate→seal→render**，明说签发
  是人的动作；(6) **丢失的记录不假装还在**：N2 / N4 视为记录已失，在各自项目的设计阶段做
  一次重扫，扫到的登记为新发现，旧编号作废。 ← **裁定**
- **B 窄交付。** 每个项目只交自己的动词；闸、门、UI 全部推到 Wave G，逐条登记为具名缺口。
- **C 逐项判断。** 由每个项目的设计自己决定交到哪。

**★ 推荐 A 的诚实代价**

1. **Wave F 明显变重。** F-A4 要多做一块本来属于 Wave G 的 dashboard；F-A3/F-A4 各多两条
   判断逻辑，而判断逻辑要走完整独立复核（复核法 1），等于多几轮审查成本。
2. **修好空绿门之后，一些今天显示绿色的客户会翻成红色**，人要多签几份例外声明。这是好
   事，但它会让「年结准备度」这块屏幕在一夜之间难看很多。
3. **重扫丢失的记录要多花一条 lane 的钱和时间，而且不保证扫得回原来那一条**；如果原来那
   条是从别的角度看出来的，可能就永久丢了。
4. **渲染器那一条要改排期**：第一次真实的封存 + 复现演练要排在 N3（补三种图表）**之前**，
   N3 会晚一点落地；同时镜像仓库要长期付费保存每一版渲染器镜像、DR-render 的配方每版跟着
   更新、每次改渲染器都当准仪式办。不这样做的代价是：七年后拿不回当年的字节——而这个承诺
   是写给监管和客户看的。

**触及的法/裁定**：法 29（live eval 是每个 wave 的验收门）· 法 31（没拒绝过的墙不是墙）·
法 27(2)（缺席不是证据）· 法 22 / ADR-048（合成标注）· 法 8（仓库是记录系统）· 复核法 1 ·
E-R14（七年可复现；签字正本保存而非重生）· 法 70（渲染重排队重新推导、双摘要）· ADR-020
（DR 全保真档）· ADR-0064 / T17（grant 要由已上线的调用方命名）· ADR-0072⑤（BEE 推迟；
OD-11 UX 底板先行）· 法 66（四家事务所不可互换）· P19 契约。

## R-E · 真正的零散题（无法被任何原则了结）

**只有一条。**

- **A3-M-60day —「60 天」这个数字本身。** 为什么无法归入原则：TA-P1 能定**谁**可以按那
  个宽免掣，但没有任何原则能推出**应该是 60 还是 90 还是 45**——它是一个经验取值。它也不
  阻塞：F-A3 可以用 60 建、用数据调。**处置（已记入 ADR-0074 R-A）**：两道同用 60 天，
  F-A3 验收电池记录真实停车频率，语料跑完后由 owner 调一次。

（另有两条被**折叠**而非留白：F-A8-M6「无白名单是否排除非公网地址拒绝名单」已并入 TA-P3
的附带确认；`classify` lane 的外送定性已提升为 TA-P3 的正式成员 F-A7-M1。）

## R-F · 两份采集意见相左之处，以及取舍（**已全部写进 ADR-0074**）

1. **同一道空绿门被两份采集**各自认领。**取舍：按「谁产出被度量的事实」切开**——银行度量
   口径归 F-A3，未编码凭证归 F-A4，第一抽屉的 P-3 留 F-T4。已写进 TA-P14。
2. **同意的形状三份不同**。**取舍：三者不冲突，它们说的是三个不同的时刻**——能确定客户时
   逐客户签、结构上不可能有客户时用所级窄用途 + 输出限制、根本没有客户内容外送时不需要
   同意。已合成 TA-P3 的选项 A。
3. **法 21 的射程**。**取舍：两者相容**——法 21 管的是「按周期**过帐**的带子」，不管「有没
   有一个时钟能唤醒她」。把这句话说出口是 TA-P5 选项 A 的核心。
4. **收据的读法**。**取舍：不冲突**——DEFINER 包装器仍可**接受 SQL 文本作参数**，它加的只是
   「读与收据同一个事务」这一件事。已在 TA-P4 写明。
5. **计量的射程**。**取舍：以源头为准**——「Per-call usage」没有 LLM 限定，全覆盖本就是现行
   姿态。摘要那一处「LLM」是漂移，列入 harness sweep 的文档修正（TA-P13）。
