## PART 1 — DECISIONS (append-only)

### ADR-001 — Greenfield rebuild on a fresh repo + fresh Supabase project
**Decision:** Rebuild Clara in a new repo (`clara-rebuild` → `github.com/mosaladtaooo/clara`) and a new Supabase project (`clara-rebuild` = `bzecqklouchkmdmdxlln`, ap-southeast-1, PG17). The prior build (`initial acc software skillmd` + `belcort-shared`) stays frozen read-only as the audit's evidence until Phase-5 sign-off.
**Why:** The Phase-1 audit found the prior build's "go-live-ready" claim structurally false (235 verified findings, 11 failure patterns) — the fix is a re-architecture of the orchestration/state/governance/UX layers on a mostly-salvageable DB layer, not a patch. Evidence: `docs/audit/`.

### ADR-002 — The four firm-killing invariants are STRUCTURAL DB guarantees (Gate-1 C3)
**Decision:** Client attribution (≥0.95, DB-gated), provenance binding (`source_doc_sha256`+`document_id` validated in-txn), wake authority (allowlist per wake kind), and write authorization (structural read-only agent role — no EXECUTE on writers + `default_transaction_read_only`) are enforced in the DB, not by model/prompt discipline. Everything judgement-flavored (coding, materiality, close-readiness) stays visibility-first.
**Why:** The audit proved the prior build's prose-only gates leaked (the read tool could write — SDT-001; provenance unvalidated — GAP0-1). Draw the hard-constraint boundary exactly where the prose demonstrably leaked. Ref: ARCHITECTURE §0/§3.

### ADR-003 — Maker/checker: modelled always, hard-gate high-stakes only, agent never signs (Gate-1 C4)
**Decision:** Every entry records maker + checker as distinct identities. Distinct-approver is a HARD DB gate only on the high-stakes lane (tax-affecting, closed-period, large-amount, year-end, opening balances) where the firm has ≥2 eligible staff; routine entries keep the one-person flow; solo firms record a self-approval attestation. The agent can never satisfy a human sign-off.
**Why:** Audit-defensible segregation of duties without breaking small-firm reality.

### ADR-004 — KB = two-layer Karpathy wiki that informs but never decides (Gate-1 B)
**Decision:** Replace the prior write-only memory-note layer with a per-client Clara-maintained markdown **wiki** (ingest/query/lint, provenance-cited, injected into every context pack) over a thin **typed authority** layer (user-gated coa-mapping rules, the ≥0.95 gate, first-class open-question objects). The wiki informs every decision but never selects an account or lowers a gate; wiki content is inert data on read. Per the Karpathy LLM-wiki pattern. Supersedes the stale prior KB design notes.
**Why:** A compounding client-knowledge layer without an LLM-written file gating money. Ref: ARCHITECTURE §5, PRD §6a.

### ADR-005 — Counterparties split + INTRINSIC same-transaction subledger (Gate-1 C2)
**Decision:** Port the proven alias/normalise + recon-hint machinery; build a first-class id-keyed counterparty entity; counterparty narrative lives in the wiki. Subledger maintenance is intrinsic to the coding/receipt execution — the audited write composes the GL leg + the AR/AP open item in ONE transaction. No path posts the GL leg without the open item.
**Why:** Structurally kills the F3 "dead subledger chain" (the audit's #1 theme — the prior build's subledger writers had zero callers). Ref: ARCHITECTURE §3.5.

### ADR-006 — v1 scope = the compliance-correct core (Gate-1 C5)
**Decision:** SST done right (taxable-period model incl. DG variations, service-tax payment basis + s.11(2) 12-month rule, dual-registrant separation surviving export, maintained rate/sector schedule, SST-02, bad-debt relief); live AR/AP subledgers + FA register + depreciation + disposal; honest MPERS financial statements **including the cash-flow statement** (MPERS S.3 requires it — the Gate-1 "SoCE+notes" floor would itself overclaim without SCF); the draft tax computation as the LAST v1 slice (may slip to v1.1); payroll = coding + deadline calendar (no engine); inventory = periodic closing-stock at close.
**Why:** Matches the prior build's ADR-044 ambition, grounded in `docs/phase2-research/accounting-practice-map.md`; the SCF inclusion was surfaced + owner-ratified at Gate 2.

### ADR-007 — Event-driven state layer + context packs + freshness (the North-Star spine)
**Decision:** Every audited write appends a domain event + a transactional outbox row; a relay drives projections + wakes (at-least-once + idempotent consumers). Before any accounting decision Clara retrieves a fresh context pack carrying a books-version token; a stale token forces re-fetch. A declarative, versioned trigger taxonomy routes each event type.
**Why:** The prior build had no event layer, no context pack, no freshness (audit A-1..A-7) — stale figures replayed as authoritative. Ref: ARCHITECTURE §2, PRD §7.

### ADR-008 — Runtime = Vercel AI SDK 7 + Workflow DevKit, self-hosted on our own Postgres (Gate-2)
**Decision:** Adopt the AI SDK 7 model layer + Workflow DevKit durable substrate (`@workflow/world-postgres`), self-hosted on the project's own Postgres, behind a swap-seam. Named fallback: LangGraph JS + PostgresSaver. Model-agnosticism is "keep the provider seam + a tested exit plan," NOT a hard veto (Codex-reframed). The incumbent OpenAI Agents SDK and the Claude Agent SDK were excluded (no durable step engine / model-lock respectively).
**Why:** The #1 prior-build failure was process-local state lost on restart (Grt-*). Durable execution for agents is the 2026 convergence; every serious TS durable-agent lane builds on the AI SDK model layer. Three independent lanes concurred. Preconditions: the Slice-0 spike (passed) + the C6 tracing checklist. Ref: `docs/phase2-research/runtime-recommendation.md` (+ addenda, corroboration, sdk-gap-analysis, codex-cross-check).

### ADR-009 — Durable-engine step memoization is NOT exactly-once; DB idempotency keys are the mandatory floor
**Decision:** Every mutation carries a stable idempotency key (unique; returns the original receipt on duplicate). The workflow engine reduces re-execution but cannot guarantee exactly-once — a step's DB txn can commit and the worker die before the engine records completion, so replay may re-invoke it.
**Why:** Empirically proven by the Slice-0 spike's kill-after-commit test (T4): the engine re-invoked a committed step; only `ON CONFLICT (op_key)` kept the books at one posting. Codex flagged this as the strongest counter-argument and it was confirmed. Ref: ARCHITECTURE Appendix A, `spike/RESULTS.md` T4.

### ADR-010 — BINDING workflow-versioning policy (no run pinning on self-hosted WDK)
**Decision:** A deployed workflow body is immutable once any run of it can be in flight; every behavioural change ships as a new `_vN` export (old export retained until zero non-terminal runs reference it); enqueue sites target the newest version; renaming/deleting an export with in-flight runs is forbidden. Enforced by a CI freeze-lint that golden-hashes each frozen workflow + its import closure and compares append-only vs `origin/main` (a changed/removed/renamed frozen entry is a hard REJECT); `"use workflow"` files must be frozen+registered.
**Why:** The spike (T6) proved self-hosted WDK has no run pinning — an in-place edit silently changes the un-executed remainder of every in-flight run (a silent-correctness hazard for accounting). Name-versioning fully mitigates it. Ref: ARCHITECTURE Appendix A.

### ADR-011 — Tracing: Clara-controlled storage at launch; vendor export gated on DPA + MIA client authorization (Gate-2 C6)
**Decision:** The runtime writes full-content run traces into our own Postgres. Cloud-vendor trace export ships feature-flagged OFF, enabled later only after: an executed DPA, firm-facing client authorization (MIA By-Laws require *specific* authority to disclose outside the firm — a DPA regulates the processor but does not itself confer it), documented PDPA cross-border basis, short retention, tested deletion, and field-level minimization. When enabled, start minimized, not blanket full-content.
**Why:** The prior build exported every firm's chat/OCR/tool payloads to a vendor by default (GAP1-8). Two reviewers + MIA By-Laws converge: our own store covers debugging/audit; a third-party copy of client books is a professional-confidentiality decision, not a debugging convenience. The owner initially preferred full-content-under-DPA; the Codex cross-check + MIA finding moved the launch posture to self-controlled-first with owner consent. Ref: `docs/phase2-research/codex-cross-check.md` Q2.

### ADR-014 — Runtime host = Fly (a long-lived Node process for the WDK world)
**Decision:** The Clara agent-runtime service (`packages/runtime`) is hosted on **Fly**, region `sin` (Singapore), completing the greenfield three-plane topology: Postgres on Supabase (`ap-southeast-1`), the Next.js dashboard on Vercel, and the runtime on Fly. The WDK world needs a persistent worker (ADR-008/009: durable execution on our own Postgres), which rules out a purely serverless/edge runtime; a long-lived process on Fly in a Supabase-adjacent region is the shape the double-verified runtime-recommendation research selected (ARCHITECTURE §4.0, 2026-07-17). What this fixes is the *choice of host*, not the requirement (a long-lived process co-located with the DB) — supersede with a new ADR if a later deployment-slice constraint (WDK worker lifecycle, scale, or cost) favours a different long-lived host.

### ADR-015 — Write-authorization is lane-split by GRANT, not detected at runtime (Slice 2 C3-iv)
**Decision:** The structural read/write-authorization boundary (Gate-1 C3, invariant 4) is realized by **splitting each mutating writer into two entry points that trust exactly one identity source** — a *human* entry (`draft_entry`, `approve_entry`, …) granted only to `clara_authenticated`, trusting `request.jwt.claims`, with firm = the sub's LIVE active membership (live revocation); and a `wake_*` entry granted only to the wake role(s), trusting the wake credential, with actor = the global agent user (never `on_behalf_of`) — over a shared, **ungranted** internal `_core`. There is **no** wake variant of `approve_entry`/`reverse_entry`: agent-never-signs is the *absence of an entry point*, not a runtime check. Read scoping is **role-pinned in the RLS policy** (human policy → `jwt_firm()`, agent policy → `wake_firm()`), never a single dual-source resolver; and a firm's parentless writes stamp the writer's already-validated firm, never a re-derived ambient `coalesce(wake, jwt)`.
**Why:** The original design detected the lane *inside* the writer by role membership. This is **impossible** (empirically confirmed, PG16): inside a `SECURITY DEFINER` function PostgreSQL sets `current_user` to the function owner and `session_user` to the login — the `SET ROLE`'d caller is invisible. Deciding the lane by *which function you hold EXECUTE on* makes a forged `request.jwt.claims` in an agent/runtime session inert (the agent roles hold no EXECUTE on any human entry point; the runtime login is not a member of `clara_authenticated`) with no in-function detection, and stamping the validated firm blocks a foreign `wake_secret` from redirecting a human write. Ratified after a mandatory dual-lane adversarial review whose **design pass AND code pass both returned FLAWED first** and were corrected before merge (the design's impossible in-definer detection; the code's proactive-consume race, an approved-entry line-reparenting hole, cross-firm credential-revocation scoping, an agent-as-owner lockout, a `shares_firm` oracle, and non-superuser deploy blockers — all reproduced-closed). Ref: ARCHITECTURE §3.2; Slice-2 design v2 §A.

### ADR-016 — The event spine's ratified semantics (Slice 3)
**Decision:** The ADR-007 event spine is realized with these owner-ratified semantics (grilled 2026-07-18): (1) **staleness scope = client + firm-level** — a client-A context pack is stale iff a later event exists with `client_id = A` or `client_id IS NULL` (firm-level); other clients' events never stale it (an UNASSIGNED `document.ingested` is firm-level and stales every pack — accepted asymmetry). (2) **Freshness enforcement = a structural DB gate on the agent lane only** — `wake_draft_entry` requires a books-version token; `CLR12` on staleness, with a commit-time RECHECK after sequence allocation that makes the guarantee airtight against the check/commit race (the DB refuses to commit an agent draft whose *submitted* token is stale; binding token→pack-origin is a trusted-runtime contract, Slice 4, wake-secret precedent). This NARROWS ARCHITECTURE §2.3's "a write asserts the token" to the wake lane; human writers keep the live UI + the per-entry revision-token approve gate. (3) **Uniform emission** — every audited writer appends its event(s) in the same transaction (admin writers included; `mint_/revoke_wake_credential` exempt as runtime plumbing). (4) **Relay output = a durable `wake_intents` queue** (exactly one row per wake-bound event; Slice 4 drains). (5) **Taxonomy = append-only versions behind a guarded singleton active pointer, fail-loud** (an uncovered type dead-letters that event; a missing/empty pointer HALTs the relay). **Slice-3 routing is event-type-only** — ARCHITECTURE §2.4's predicate dimensions (risk, materiality, workflow/period state, freshness) land with the slices that own that state; versioned-data + testability is what is structural now. (6) **Context pack = a typed pack of what exists** (`pack_schema_version`, single-snapshot coherent, approval history from the base tables — the log begins at the 0005 `books.baseline` cutover). Also owner-ratified: **archived-client drafting is hard-blocked in the DB for BOTH lanes** (corrections remain possible via `reverse_entry`).
**Why:** Grilled decision-by-decision with the owner, then hardened through a dual adversarial design review (native + Codex, each with a delta re-review) and 15 empirical probes — which reproduced two real deadlocks (an FK-induced cycle killed by giving the log/counter NO foreign keys, and a **pre-existing Slice-2 approve/reverse deadlock** fixed by an original-before-mirror lock order) and verified the gap-free per-firm sequencing that makes checkpoint relaying lossless. Ref: migration `0005_event_spine.sql` (finding tags inline), `packages/db/README.md` deploy contract, Slice-3 PR.

### ADR-018 — The document pipeline's ratified semantics (Slice 5)
**Decision:** Slice 5 realizes the document pipeline with these owner-ratified semantics (grilled 2026-07-18; contract `docs/plan/slice5-document-pipeline-contract.md` v1.2 + companion `slice5-migration-0007-design.md`): (1) **OCR egress = a two-tier gate** — build/ship NOW on synthetic + firm-own data; REAL client documents reach the vendor only after the owner evidences an ADR-011-grade bundle (executed DPA + engagement-letter processor-disclosure clause **firm-wide across every active client** + documented PDPA cross-border basis + no-training/limited-retention terms + minimized payload + tested deletion), enforced fail-closed by `CLARA_DOC_EGRESS_APPROVED` whose OFF state parks OCR tasks at the pre-dispatch claim gate (`queued→held_egress`; no run binds, no vendor call); the real vendor adapter has NO dev bypass. (2) **Engine pin** = Azure Document Intelligence prebuilt-layout v4.0 (API 2024-11-30), Southeast Asia, S0 — snapshotted per processing task; the law stays vendor-agnostic. (3) **Chat attachments ship as a CAPTURE door** (amends the Slice-4 ruling of record: chat may never write books; evidence ingestion is allowed): chip + persist + lane, submit blocks on intake adoption so the `{type:'attachment'}` part is present at `begin_chat_turn`; `chatTurn` stays frozen at v1 so Clara does NOT perceive attachments in-turn — perception (a parts-aware `chatTurn_v2` + a firm-scoped unassigned-document read tool) is Slice 6, and the UI copy states this honestly. (4) **Storage is content-addressed write-once** (`firms/{firm}/docs/{sha256}.{ext}`, upsert=false, never moved, never deleted by any routine principal); the runtime seals the sha↔bytes bond by hashing the spooled stream and re-hashing a readback after upload; the browser never holds a storage credential (transport = runtime-owned store-and-forward on Fly — never the 4.5MB-capped Vercel proxy, never direct-to-storage). (5) **Multi-client filings** — ONE document row per (firm, sha256) + historical `document_filings`; unassigned ⇔ zero active filings; provenance is filing-bound and two-layer: admission derives `filing_id` server-side in `_draft_entry_core` + enforces the citability law (ACTIVE filing AND `bytes_verified_at`), `approve_entry` re-affirms, and the DEFERRABLE belt validates congruence against the BOUND filing regardless of retired state — so the correction transaction commits while history stays verifiable. (6) **Both legacy ingest writers retired** (bodies → deterministic refusal, EXECUTE revoked, allowlist row deleted); the verified-intake finalizer is the SOLE document creator (closes HIGH-12: a caller-claimed sha is never again ingestable as evidence). (7) **Attribution = deterministic two-lane, no model, no autonomous filing**: a net-new `matcher` consumer on the generalized relay (own advisory-lock leadership, own `(consumer,firm)` checkpoints, own dead-letters + consumer-specific redrive) subscribes to `document.extraction_completed`; lane 1 (authorizing) = a unique role-aware HARD identifier hit recomputed server-side inside `record_rule_resolution` (callers supply neither client nor confidence; EXECUTE held by the `clara_runtime_login` login DIRECTLY — a deliberately narrow surface a pooled SET-ROLE session cannot reach); lane 2 (advisory) = exact name/alias hits as candidates only; conflicts abstain with the conflict REPRESENTED (identifiers deliberately non-unique across siblings); assignment stays a human act in Slice 5; all model machinery waits behind the Phase-5 eval gate; confidence never displays as a percentage. (8) **Correction = refuse-until-reversed + a guided case**: `retire_document_filing` refuses with structured blockers while live posted entries OR live drafts cite the document; the sanctioned path is preview (read-only blast radius) → propose (immutable hash-bound plan + books_version; any intervening event stales it) → approve by a DISTINCT eligible checker (attestation is not a bypass when another checker exists — the 0004 house law; solo-attest only when solo) requiring an authoritative human/rule DESTINATION attribution (a ≥0.95 document-subject resolution for the target client) → ONE bounded transaction: whole-consequence reversal mirrors, drafts → a real `withdrawn` journal status (never deleted; lines frozen; excluded from every book-effect read, included in history), source filing retired, target filing ensured, one aggregate `document.correction_applied` + ordinary child events; closed periods HARD-BLOCK at approve (honest-state: no period model exists yet — `_correction_period_state` is the single extension point reporting `no_period_model`); approve is human-only forever. (9) **Document metering = a separate fail-closed budget** with durable reservation semantics (conservative declared-size reserve → post-scan resize → settle at actual pages → refund on failure; adoption TRANSFERS the charge, the legacy-upgrade branch charges fresh; settled usage counts against a lowered limit — conservative daily accounting). (10) **Retention = honest states**: `unanchored` (no sentinel; undeletable while unanchored) → first filing anchors (FY-end + statutory offset + 7y; conservative floor recorded when FY data is missing) → MAX across active filings; `retain_until` persists across unanchor→re-anchor so floor-never-shorten stays monotonic; audited admin legal holds independent of the clock; no purge machinery in v1. (11) **Freshness narrows ADR-016's asymmetry** (owner-ratified delta): a null-client event carrying a `document_id` is relevant to client X iff an ACTIVE filing document→X exists — an unassigned document's ingest/extraction events stale NOBODY, `document.filed` stales exactly its filed clients, `document.correction_applied` is exempt (its children carry the staleness); non-document null-client events keep firm-level staleness. (12) **Taxonomy v2 activated in-migration** with full coverage + the quiesce-aware cutover protocol (residual v1 document intents/held rows cancelled with an audited reason). (13) **MyInvois UBL XML = store-only** (flagged "e-invoice — stored, not parsed") until the coding slice. **As-built §3.10 amendments of record (surfaced by the build's independent lanes, adjudicated as matrix omissions):** migration `0008_runtime_read_surface.sql` adds READ-ONLY runtime visibility on (a) the matcher's lane-2 inputs (extractions/regions/clients — the granted aliases/identifiers row proved matcher-side computation was the intent) and (b) the runtime's OWN control tables (intakes/processing tasks/reservations — the §3.9 reconciler design requires seeing queued-unbound tasks; the read grant closes an otherwise-irreducible finalizer crash window); DML remains writer-only.
