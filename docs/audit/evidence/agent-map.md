## 1. HTTP surface (`agent/src/http/server.ts`)

Auth model: every `/firms/:firmId/*` route requires a Bearer JWT whose **signature is verified** (HS256 shared secret if `SUPABASE_JWT_SECRET` set, else Supabase JWKS; issuer `${SUPABASE_URL}/auth/v1`, audience `authenticated`; auth.ts:93-125) — then an IDOR guard `caller.firmId === routeFirmId` (server.ts:299-301). CallerIdentity = `{firmId, userId, role∈viewer|bookkeeper|admin|owner, jwt}` from `firm_id`/`firm_role` claims (top-level or `app_metadata`; auth.ts:36-44). Decode-only helpers (`parseCaller`) are explicitly not auth (auth.ts:46-49). CORS: exact-origin allowlist from `ALLOWED_ORIGINS`, echo-if-listed, never `*`; empty list denies all cross-origin browsers (cors.ts:23-38). Body ceiling `MAX_BODY_BYTES = 150MB` (sized for 5×20MB base64 attachments; server.ts:61-67); separate 32,768-char message cap (server.ts:345).

Routes:

## 2. The runtime loop (`agent/src/runtime/openai/*`)

Seam: `AgentRuntime` = `startRun / streamRun / resolveClarify / pollRun / wake` (runtime/types.ts:147-158). `OpenAIRuntime`:

- **Run state is 100% process-local**: `private readonly runs = new Map<string, RunRecord>()` (runtime.ts:136). `RunRecord = {context, policy, input, status, startedAt, lastTouchedAt, settledAt?, streaming?, output?, sessionId?, pending?{clarifyId,question,choices,resolve}}` (runtime.ts:80-99). Nothing about a run — status, pending clarify, tool calls, output — is in the DB except the final assistant text appended to `chat_messages` at settle. **A process restart loses every active run and parked clarify.**
- `startRun`: mint UUID runId, build a JWT-bound ToolContext (policy `interactive`, actor `'agent'`), fold history + attachment manifest into the input (`buildRunInput` returns a bare string on first turn, else `AgentInputItem[]`; runtime.ts:66-78), register the record, return — **the model does not start until the SSE attach**.
- `streamRun`: firm-binds the runId (foreign firm reads "unknown run" — a runId is a bearer capability; runtime.ts:211-215); terminal replay for settled runs (completed replays `done`, else "run already settled"); single-flight `streaming` flag (second live attach → error, never a second model loop; runtime.ts:219-228). Loop: `run(agent, input, {context, stream:true, maxTurns:40})` (MAX_TURNS=40 for onboarding's dozen-plus tool turns; runtime.ts:33-39) → `pump` maps SDK stream events via `mapStreamEvent` (only `response.output_text.delta`→delta and tool_call/output/reasoning items→tool breadcrumbs; events.ts:38-67) → then a **while-interruptions loop**: `clarify_tool` interruptions (the tool is `needsApproval:true`, so the SDK pauses; tools.ts:47-64) create an answer Promise, yield `clarify_request`, and `await answerPromise` — **the generator suspends in-process** until `resolveClarify` fires; then `result.state.approve(interruption)` and re-`run(agent, result.state, …)` resumes the SAME run via RunState (runtime.ts:236-256). **Any other needsApproval interruption is auto-approved** (runtime.ts:249-252). Terminal: `settleRun('completed', finalOutput)` + `settleInteractive` (best-effort assistant-turn persist) + yield `done`; on throw: settle failed, log, yield `error` (runtime.ts:258-269).
- `resolveClarify`: firm-bound; sanitizes the answer (`clean`: control-char strip, «» strip, 4000 cap; inject.ts:6-23), attaches clarify-ride documents to `rec.context.documents` + appends the layer-computed attachment manifest (filename/type/bytes/sha256; runtime.ts:48-58,301-322), resolves the parked Promise. The clarify tool's execute then returns the answer **plus a hard-coded [flow-control] directive** re-stating the clarify loop discipline (tools.ts:56-63).
- `pollRun`: `{status, output?, pendingClarify?, startedAt}`; wrong firm reads `{status:'failed'}` (runtime.ts:324-336).
- Eviction: settled runs kept 10min for replay; running runs with no stream and no pending clarify evicted after 30min idle; wake runs deleted at drain-settle (runtime.ts:40-41,484-495).
- One `Agent` per ToolPolicy, lazily built, shared instructions, differing tool set (runtime.ts:161-173).
- In-memory vs DB, summarized: **DB** = chat_sessions/chat_messages (user + final assistant text, artifact column reserved), plus every book mutation via audited fns. **In-memory only** = run registry, run status, pending clarify, streamed deltas, tool-call history, wake batches (wakeGate pending map), hub subscriptions, bulkApprove `active` set + in-flight loop.

## 4. sqlGuard.ts — the exact SELECT-only mechanism

`assertReadOnlySql(raw)` (sqlGuard.ts:57-85) is a **lexical** filter, self-declared "defence-in-depth ONLY" (sqlGuard.ts:4-7). Mechanism, verbatim:
1. Strip comments: `sql.replace(/--[^\n]*/g, ' ').replace(/\/\*[\s\S]*?\*\//g, ' ')` (line 47).
2. Reject empty; strip one trailing `;`, then reject any interior `;` — `if (body.includes(';')) throw … 'multiple statements are not allowed'` (63-64).
3. Head check: `const lead = body.toLowerCase().replace(/^[(\s]+/, ''); if (!lead.startsWith('select') && !lead.startsWith('with')) throw` (66-69).
4. ANYWHERE_VERBS `['insert','update','delete','merge','truncate','drop','alter','grant','revoke']` rejected as whole words anywhere: `new RegExp('\\b'+verb+'\\b','i').test(lowered)` (17,73-77).
5. STMT_START_VERBS (`create,comment,copy,call,do,vacuum,analyze,reindex,cluster,refresh,lock,set,reset,begin,commit,rollback,savepoint,prepare,execute,listen,notify`) rejected only when heading a statement or a CTE inner statement: `(^|\(|\bas\s*\()\s*verb\b` (21-43,79-83).

What it therefore does NOT catch: **a plain `SELECT some_security_definer_write_fn(...)`** — e.g. `select draft_entry('{...}')` — contains none of the banned verbs and starts with `select`, so it passes the guard and reaches `ctx.query` → `rpc('agent_select', {p_sql})` (db.ts:58-65). The real protection is claimed DB-side ("`app.agent_select` — RLS-scoped, READ ONLY, statement-timeout", db.ts:6-9; "the EXECUTE-only role has no INSERT/UPDATE/DELETE/DDL grant", sqlGuard.ts:3-6) — but the role DOES have EXECUTE on the SECURITY DEFINER write fns (that's how the curated tools work), so whether the wrapped-fn call mutates depends entirely on the `agent_select` implementation in `db/v2/26-fns-session.sql` (outside this map's corpus). This is the recorded SDT-001/SEC-001 mutation-bypass path, and it also bypasses the tool layer's scope-gate + actor-injection even when the DB blocks the write. Also note `db.ts:62` trims leading whitespace because the DB guard "anchors on ^(select|with)" — confirming the DB-side check is itself partly lexical.

## 5. Wakes (wakes.ts, wakeGate.ts, wakeCredential.ts, runtime.wake)

Ingress: Supabase DB webhooks POST `/hooks/supabase/:firmId` with the per-firm HMAC bearer (`firmWebhookSecret(master, firmId)`; the owner sets each firm's `belcort_webhook_config.webhook_secret` to that derived value — one leaked row burns one firm's lane; wakes.ts:76-84). `classifyHook` (wakes.ts:120-155): validates table/op/condition shapes; `books_changed` on an allowlisted books table (wakes.ts:50-64, incl. `export_artifacts`; `proactive_notifications` special-cased to a hub `proactive` nudge) → the **agentless** coalesced `books` SSE nudge (2s trailing window, drops-not-resets; hub.ts:61-80); any other condition + record id → a **wake**. Condition→lane: `kb_proposal_open`→kb, `document_triaged`→documents, `workbench_committed`→workbench, `bank_line_matched`→workbench, **everything unknown defaults to the safe `proactive` lane** (wakes.ts:30-39). Allowlisted record extras only: id/client_id/document_id/entry_id/line_id/action (`/^[a-z_]{1,32}$/`).

Governor (`wakeGate.ts`): batches per `(firmId, condition, clientId)` in a 15s trailing window (reset per arrival, capped at 4× from first arrival); refires on the same record replace (dedup); batch cap 30 with overflow counting; per-firm rate cap 6 new windows/min — excess submits **dropped** with honest `rate_limited`; timers unref'd; `clearPending()` at shutdown drops unfired hints without firing (main.ts:236). **Wakes are explicitly at-most-once lossy hints** (wakeGate.ts:9-14) — the notification/read surfaces are the recovery path. Not durable: no queue, no retry, no persistence.

Dispatch honesty: without `SUPABASE_JWT_SECRET` there is no wake-credential minter → the webhook answers `dispatched:false, 'wake dispatch not configured'` without queueing (server.ts:204; runtime.ts:347-349).

Credential (`wakeCredential.ts`): mints a **30-min HS256 JWT signed with the project's legacy shared JWT secret**: `role:'authenticated'` (same RLS plane as a human, never service_role), top-level `firm_id`, **`firm_role:'bookkeeper'`**, `belcort_agent:true`, deterministic synthetic v8-UUID `sub` per firm (`sha256('belcort-agent:firm:'+firmId)`), `aud:'belcort-wake'` so the agent shell's own verifier (aud `authenticated`) can never accept it as a caller — but PostgREST does not enforce aud by default, so it is a full DB credential (wakeCredential.ts:59-89). Firm id re-checked `/^\d{1,18}$/` at mint. Header comment admits: holding the secret = ability to mint ANY firm's token (wakeCredential.ts:20-23). Wake runs must never call the session fns (chat_sessions.user_id FKs auth.users; the synthetic sub has no row; wakeCredential.ts:8-10).

Run (`runtime.wake`, runtime.ts:338-378): policy = proactive|documents|workbench-kb by kind; mints the caller; builds the fenced note `buildWakeNote` (per-kind framing + v2 read hints incl. starter SELECTs + every trigger value «»-fenced/4000-capped; inject.ts:30-96); batch client_id becomes the run's active scope; actor `'agent'` (LOAD-BEARING: the DB self-wake fences key on `actor is distinct from 'agent'`; runtime.ts:362). Deterministic short-circuit: a `je_needs_human` proactive wake skips the model entirely — reads `journal_entry_detail`, files `record_proactive_notification` directly (runtime.ts:383-442). Otherwise a consumer-less throwaway run: `drainWake` iterates its own streamRun, 90s deadline, settle-hook `onWakeSettled` → payload-less hub `proactive` nudge, record evicted at settle (runtime.ts:444-468).

**Can a wake mutate?** Yes, by policy design: `proactive` can write exactly `record_proactive_notification`; `workbench-kb` can write evidence/hints/notifications; **`documents` can call any write tool except the 5 onboarding fns** (buildTools.ts:25) — approve_entry, reverse_entry, run_depreciation, record_year_end_close etc. are all policy-reachable in the [documents] lane (its doctrine framing "act on the human's verb" is the only narrowing; inject.ts:38-39). Plus every lane can run `query_books` — so the §4 SELECT-wrapped-definer path is reachable from any wake too. "Speak-never-act" is per-lane, not universal.

## 6. Session/transcript persistence (http/sessions.ts)

Tables/fns (db/v2/16-tables-session.sql + 26-fns-session.sql): `chat_sessions` (per firm+user+scope; status active|archived; `active_run_id`), `chat_messages` (id = seq, role, content, reserved `artifact` jsonb, created_at). Every call rides the CALLER's JWT (per-call `createClient` with `Authorization: Bearer` header; sessions.ts:117-123); writes via audited fns `ensure_chat_session / append_chat_message / set_active_run / reset_chat_session`; reads are direct RLS SELECTs. User turn persisted pre-run; assistant turn persisted RAW at settle, **shaped at read** (directive-block strip + artifact-fence extraction against the 7-type allowlist regex; sessions.ts:43-72,229-249). `loadHistory` feeds the model's cross-turn memory: last ≤40 (cap 100) turns, chronological, assistant turns de-fenced (sessions.ts:253-270). Reset TOCTOU handled: settle-append into a refreshed scope re-ensures the fresh session (main.ts:162-170).

**NOT persisted**: run status/registry; pending clarify (question, choices, resolve); streamed deltas (a crash mid-run loses everything after the user turn); tool-call/tool-result history (only ephemeral SSE breadcrumbs); artifacts as typed rows (the jsonb column is reserved, never written — cards live as fenced text inside the assistant turn); wake runs (no session at all — synthetic sub can't FK auth.users); clarify answers as turns; bootstrap-chat transcripts (session-less by design). A clarify-length run can outlive the caller's ~1h JWT → the settle append 401s → a named "transcript gap" (main.ts:171-176, recorded deferral).

bulkApprove: `start` = `create_job(kind:'approve_bulk', payload:{remaining})` awaited (caller gets jobId) + a fire-and-forget background per-id loop: poll `get_job` for pause/cancel flags (500ms), `approve_entry` per id **on the caller's raw JWT via direct PostgREST** (`postgrestRpc` — not the tool layer; audited as the caller's email/sub, never service_role; bulkApproveRunner.ts:29-59,104), `advance_job` patches `{remaining, failed}`, hub streams `job` SSE. Terminal: cancel wins; **partial failure settles `fail_job`** (relay contract — visibility over a false green); clean → `finish_job`. Restart redrive: `resumeOpen` (fired at boot-time attach of the notifications SSE and before each start) relaunches open `approve_bulk` jobs from `payload.remaining`, preserving the ORIGINAL `job.actor` string while running on the RESUMING caller's JWT (bulkApproveRunner.ts:180-193). In-process `active` Set is the only concurrency guard (single machine).

OCR: Azure AI Document Intelligence v4.0 REST (`prebuilt-layout`, api-version 2024-11-30), key auth header, `{base64Source}` POST → 202 + Operation-Location → poll 1.5s (429 tolerated) to a 120s deadline; tables rendered to TSV grids by rowIndex/columnIndex with span fill (azureDocai.ts:50-113). Composition-injected as `ctx.ocrDocument`; absent env ⇒ `extract_document` answers "OCR is not configured" (honest no-OCR deploy; main.ts:124-131). Key never reaches model or DB paths.

## 9. NOTES — suspicious / audit-relevant findings

1. **[HIGH, known SDT-001/SEC-001] `query_books` cannot lexically stop `SELECT write_fn(...)`.** sqlGuard.ts:57-85 blocks verbs, not function calls; `select approve_entry(1,2,'x')` passes to `agent_select`. Whether it mutates is decided solely by `agent_select`'s DB-side READ ONLY posture (db/v2/26, not in this corpus). Even if blocked, the path skips scope-gate + actor injection. Reachable under EVERY policy including all wake lanes (buildTools.ts:376).
2. **[HIGH] `documents` wake policy is a blocklist, not an allowlist** (buildTools.ts:25): a [documents] wake — triggered by any `document_triaged` audit insert — may call approve_entry, reverse_entry, run_depreciation, record_year_end_close, edit_entry, build_export, upload_document… "act on the human's verb" is doctrine framing only (inject.ts:38-39). "Speak-never-act" is not universal (matches CLAUDE.md's audit-limited framing).
3. **[HIGH] No durable run state**: `OpenAIRuntime.runs` is a process-local Map (runtime.ts:136); a Fly deploy/restart kills every in-flight run and parked clarify (an onboarding interview dies mid-clarify, `active_run_id` dangles until the 15-min reset age-out, server.ts:423-426). fly.toml pins ONE machine for exactly this reason (fly.toml:8-15) — availability and durability are both single-process.
4. **[MED] Wake ingress is best-effort/lossy by design**: rate-cap drops (`rate_limited`), shutdown `clearPending`, at-most-once, no persistence/retry (wakeGate.ts:9-14, main.ts:236). Fine per doctrine ("wakes are hints") but it means the notification surfaces are the only safety net.
5. **[MED] Wake JWT secret = mint-any-firm capability** and the minted token is a real PostgREST credential (aud unenforced by default; wakeCredential.ts:76-83). Container already holds service-role, so no new tier — but `firm_role:'bookkeeper'` gives wake runs human-decision fn eligibility, fenced only by tool policy (wakeCredential.ts:66-73).
6. **[MED] Wake drain timeout doesn't cancel the model loop**: `withWakeDeadline` uses `Promise.race` (runtime.ts:497-507) — on `wake_run_timeout` the run is marked failed and evicted, but the abandoned `work()` promise (the SDK loop + tools) keeps executing in the background; late tool writes can land after the run is officially "failed", and drainWake's finally already deleted the record.
7. **[MED] Auto-approval of unknown interruptions**: any non-clarify `needsApproval` interruption is silently `state.approve`d (runtime.ts:249-252) — safe only while no other tool sets needsApproval; a future SDK/tool change flips this to auto-consent.
8. **[LOW-MED] Dead native artifact/directive lane**: `RuntimeEvent` and sse.ts carry `artifact`/`directive` frames, but `mapStreamEvent` never emits either (events.ts:38-67) and the runtime yields none — cards actually travel as fenced JSON in assistant text, re-extracted at read (sessions.ts:43-60). 9. **[LOW-MED] bulkApprove resume attribution/authority split**: an orphaned job resumes on WHOEVER next opens the notifications SSE — approve_entry authorized by the resumer's JWT but audited as the ORIGINAL actor string (bulkApproveRunner.ts:188). A viewer-role resumer presumably fails role gates per id (counted as per-entry failures), and audit rows can name a person whose credential did not authorize the write.
10. **[LOW] Model-composed SQL string-building in exportTool** (journalsFySql etc.) is guarded by strict literal validators (`sqlInt/sqlDate/sqlText`, exportTool.ts:64-89) — fine today, but a fragile pattern next to `agent_select`; `build_analysis_report` runs fully model-authored SELECTs (RLS-bounded to the firm, any client, no scope gate on reads).
