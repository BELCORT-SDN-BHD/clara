# WAVE D-b SPLIT — THE CROSS-SLICE CONTRACT ROSTER.
#
# NOT a slice list. The four test-list-d-bN.txt files PARTITION the x41/x42 corpus — every
# file in exactly one of them, each declaring its own measured cell floor. The files named
# HERE are the opposite shape: each is FRONTIER-AWARE and asserts what is true at whatever
# frontier it finds, so each must run at EVERY frontier or it is not a contract at all.
#
# WHY IT EXISTS [merge-gate SF4, PR #182]. x42x-* files are excluded from the file-granular
# totality gate precisely because they belong in several places at once — which left them
# guarded by nothing but each slice list's goodwill. A later slice could omit every contract
# from its list and still pass the partition. This roster replaces that goodwill:
#   · ci.yml's db-slice-frontiers job RUNS every line below in every ready leg; and
#   · ci.yml's db-split-partition-total job asserts this roster is EXACTLY the set of
#     tests/x42x-*.test.mjs on disk — a contract that joins the corpus and not this file
#     fails by name, and a line here with no file fails too.
# The roster therefore GROWS in the PR that ships the contract, and nowhere else.
#
# THE CELL FLOOR, AND WHY THE SKIP BOUND IS PER-FRONTIER [#1041, review SPEC-1041-B]. This
# roster used to declare no floor at all, on the reasoning that "a contract's cell count
# legitimately CHANGES with the frontier". What changes with the frontier is the PASS count —
# each arm skips on the side of the boundary it does not describe — and the number of CELLS the
# roster RUNS does not move at all. That is the same conflation #1041 took out of the four slice
# lists, and until it was fixed here the roster step asserted nothing but `fail = 0`: a gate
# module (the frontier leg preloads the whole preintegration chain since #1041) that stood a
# contract cell down would have left this step green with less measured.
#
# So: `#!cells-floor:` is ONE number the run must meet at every frontier, and the skip bound is
# FOUR, one per leg, because a bound measured at the lowest frontier bounds nothing at the other
# three. MEASURED on the lane-07 cluster, 2026-09-24 — one throwaway database per frontier
# (0001..0042/0043/0044/0045), the gate chain preloaded, `--test-concurrency=1`:
#   d-b0 (0042): 12 cells · 4 pass · 0 fail · 8 skip

#   d-b3 (0044): 12 cells · 8 pass · 0 fail · 4 skip
#   d-b2 (0045): 12 cells · 8 pass · 0 fail · 4 skip
# Raise the floor in this file when a contract gains a cell; NEVER lower either number to go
# green. `packages/db/tests/ci-frontier-leg-contract.test.mjs` holds both to the leg.
